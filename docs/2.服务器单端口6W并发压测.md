**面试考点**：

- 一台客户端最多能连多少连接？→ TCP 五元组，源端口 16 位，最多约 64000（单IP单端口）
- 怎么突破这个限制？→ 多端口监听、多 IP、tcp_tw_reuse
- 高并发测试需要调哪些系统参数？→ ulimit、ip_local_port_range、tcp_mem 等
- 你测了多少并发？→ 64000（或你最终测到的数字）



## 一、数据分段

|阶段|连接数范围|每1000连接用时|特征|
|---|---|---|---|
|阶段1|0 ~ 32000|1.6 ~ 1.9 秒|快且稳定|
|阶段2|32000 ~ 33000|1.9秒 → 6.5秒|**突然变慢3倍**|
|阶段3|33000 ~ 53000|6.5 ~ 11.5 秒|慢但相对稳定|
|阶段4|53000 ~ 64000|10 ~ 14.5 秒|越来越慢，最终端口耗尽|

---

## 二、逐个阶段解释

### 阶段1（0~32000）：为什么快且稳定？

连接数少，系统资源充足：

- 客户端和服务器的 epoll 红黑树都不大，插入/查找快
- 内存充足，TCP 发送/接收缓冲区分配没有压力
- CPU 大部分时间在处理连接建立，没有内存回收的开销
- 每 1000 连接约 1.7 秒，相当于每秒约 600 个连接

### 阶段2（32000~33000）：为什么突然变慢？（最关键）

这是整个曲线的**拐点**，从 1.9 秒直接跳到 6.5 秒。最可能的原因是 **触发了 Linux 内核的 TCP 内存压力阈值**。

Linux 有个参数 `tcp_mem`，控制系统范围内所有 TCP 连接的缓冲区总内存，有三个阈值：

```
cat /proc/sys/net/ipv4/tcp_mem
# 输出类似：92715   123620  185430（单位是页，1页=4KB）
#            low    pressure  high
```

|阈值|含义|
|---|---|
|`low`|低于此值，TCP 内存不受限制|
|`pressure`|超过此值，内核进入"内存压力"模式，**限制新连接的缓冲区分配**，连接建立变慢|
|`high`|超过此值，内核可能直接拒绝新连接或丢弃数据|

**估算一下你的情况**：

- 每个 TCP 连接默认发送缓冲区约 16KB ~ 64KB，接收缓冲区约 80KB ~ 200KB
- 取保守值，每连接约 40KB（发送+接收+内核socket结构）
- 32000 连接 × 40KB ≈ **1.28 GB**
- 客户端和服务器都在同一台机器，双方都占用内存，实际约 2.5GB

这个量级很可能刚好超过了你系统的 `tcp_mem pressure` 阈值，导致内核开始限制 TCP 内存分配，新连接建立速度骤降。

**你可以验证一下**：

```
cat /proc/sys/net/ipv4/tcp_mem
# 把三个值 × 4KB 换算成字节，看 pressure 阈值是多少
# 然后对比 32000 连接时的内存占用
```

### 阶段3（33000~53000）：为什么稳定在更慢的速度？

系统进入了"内存压力"模式后：

- 每个新连接的缓冲区分配需要等待内核回收旧连接的内存，或者从预留池里分配
- epoll 红黑树变大，插入操作从 O(1) 感觉变成 O(log n) 的实际开销（n 大了常数因子显现）
- 客户端和服务器竞争 CPU，双方都在处理大量 fd 的事件
- 稳定在每 1000 连接 7~~10 秒，比阶段1慢了约 4~~5 倍

### 阶段4（53000~64000）：为什么越来越慢？

接近资源极限：

- 内存更加紧张，内核可能频繁触发内存回收（kswapd）
- 源端口逐渐耗尽，客户端 `connect` 开始出现失败重试，增加额外开销
- 系统可能开始使用 swap（如果开启了），swap 比内存慢 100 倍以上
- 最终在 64000 时端口完全耗尽，报 `Cannot assign requested address`

## 三、面试时怎么讲这个现象

面试官如果问"你压测时遇到了什么问题"，你可以这么说：

> "我用自己写的 epoll 客户端做并发测试，单端口最多测到 64000 连接。过程中发现连接建立速度在 32000 左右有一个明显的拐点——之前每 1000 连接约 1.7 秒，之后突然降到 6.5 秒。排查后发现是触发了 Linux 内核的 tcp_mem 内存压力阈值，超过 pressure 阈值后内核会限制新连接的 TCP 缓冲区分配。继续增加连接后，内存压力增大，建立速度持续下降，最终在 64000 时因为源端口耗尽（本地端口范围 1024~65535）而无法建立新连接。"

这段话能体现你：

1. 真的动手做了压测（有具体数字）
2. 会分析性能瓶颈（找到拐点）
3. 懂内核参数（tcp_mem）
4. 懂 TCP 原理（五元组、源端口限制）

## 四、如果想测更多连接（可选）

你现在已经摸到单端口上限了，要测更多需要：

1. **服务器监听多个端口**（比如 9000~9009），客户端轮流连 → 能到几十万
2. **调大 tcp_mem**：`sudo sysctl -w net.ipv4.tcp_mem="262144 393216 524288"`（单位页）
3. **调小 TCP 缓冲区**：`tcp_rmem`、`tcp_wmem`，让每连接占用内存更少
4. **加内存**：WSL2 的 `.wslconfig` 里调大 memory

但你现在阶段不需要了，64000 并发连接 + 能讲清楚上面的原理，面试足够了。

## 一、查看系统限制（排查瓶颈时用）

```
# 查看当前文件描述符上限（软限制）
ulimit -n

# 查看硬限制（能设的最大值）
ulimit -Hn

# 查看软限制
ulimit -Sn

# 查看系统级文件描述符总上限（所有进程加起来）
cat /proc/sys/fs/file-max

# 查看 TCP 内存阈值（单位是页，1页=4KB）
cat /proc/sys/net/ipv4/tcp_mem
# 输出示例：92715  123620  185430
# 分别是 low / pressure / high，×4KB 换算成字节

# 查看本地端口范围（客户端能用到的源端口）
cat /proc/sys/net/ipv4/ip_local_port_range
# 输出示例：32768  60999
# 可用端口数 = 60999 - 32768 ≈ 28000

# 查看 TCP 接收缓冲区默认值
cat /proc/sys/net/ipv4/tcp_rmem

# 查看 TCP 发送缓冲区默认值
cat /proc/sys/net/ipv4/tcp_wmem
```

## 二、修改文件描述符上限（最常用，解决 "Too many open files"）

### 临时修改（当前终端生效，重启 WSL 后失效）

```
# 设置当前终端的文件描述符上限
ulimit -n 65535

# 验证
ulimit -n
```

⚠️ **注意**：服务器和客户端要在**各自执行了 ulimit 的终端里启动**，否则不生效。

### 永久修改（修改硬限制，重启 WSL 后生效）

```
# 编辑配置文件
sudo nano /etc/security/limits.conf

# 在文件末尾加两行：
# * soft nofile 65535
# * hard nofile 65535
# 保存退出（nano: Ctrl+O 回车保存，Ctrl+X 退出）
```

然后在 **Windows PowerShell** 里重启 WSL：

```
wsl --shutdown
```

重新打开 WSL 后验证：

```
ulimit -Hn   # 应该输出 65535
ulimit -n 65535
ulimit -n    # 验证
```

---

## 三、修改网络参数（解决源端口耗尽、TCP 内存压力）

### 临时修改（重启后失效）

```
# 1. 调大本地端口范围（解决 "Cannot assign requested address"）
sudo sysctl -w net.ipv4.ip_local_port_range="1024 65535"

# 2. 启用 TIME_WAIT 端口复用（让 TIME_WAIT 状态的端口能重新分配）
sudo sysctl -w net.ipv4.tcp_tw_reuse=1

# 3. 调大 TCP 内存阈值（推迟 tcp_mem pressure 拐点）
# 单位是页，1页=4KB，下面分别是 1GB / 1.5GB / 2GB
sudo sysctl -w net.ipv4.tcp_mem="262144 393216 524288"

# 4. 调小每个连接的 TCP 缓冲区（减少总内存占用，高并发时有用）
sudo sysctl -w net.ipv4.tcp_rmem="4096 4096 4096"
sudo sysctl -w net.ipv4.tcp_wmem="4096 4096 4096"

# 5. 调大连接队列（突发大量连接时有用）
sudo sysctl -w net.core.somaxconn=65535
sudo sysctl -w net.core.netdev_max_backlog=65535
sudo sysctl -w net.ipv4.tcp_max_syn_backlog=65535
```

### 永久修改（重启后生效）

```
sudo nano /etc/sysctl.conf
# 把上面的参数写进去，每行一个，例如：
# net.ipv4.ip_local_port_range = 1024 65535
# net.ipv4.tcp_tw_reuse = 1
# 保存后执行：
sudo sysctl -p
```

## 五、监控命令（测试时另开一个终端看）

```
# 看 CPU 和内存实时占用（最常用）
htop

# 看内存使用概要
free -h

# 看 TCP 连接统计
ss -s

ss -nat | wc -l

```

## 六、报错速查表

|报错|原因|解决|
|---|---|---|
|`Too many open files`|文件描述符上限不够|`ulimit -n 65535`，改 limits.conf|
|`ulimit: value exceeds hard limit`|软限制超过硬限制|改 limits.conf 的 hard nofile，重启 WSL|
|`Cannot assign requested address`|本地源端口耗尽|调大 `ip_local_port_range`，启用 `tcp_tw_reuse`|
|`Address already in use`|端口 TIME_WAIT，bind 失败|代码里加 `SO_REUSEADDR`|
|`connect: Connection refused`|服务器没启动或端口错|检查服务器是否在运行、端口是否一致|
|服务器突然崩溃/被 killed|内存不足，OOM killer 杀掉进程|调大 WSL 内存，或调小 tcp_rmem/tcp_wmem|
