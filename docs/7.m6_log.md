## 1. 为什么需要日志

### cout 的问题

M1-M5 全程用 `std::cout` 打印，问题：

| 问题 | 后果 |
|------|------|
| 输出到终端，程序关了就没了 | 无法事后排查问题 |
| 没有时间戳 | 不知道什么时候发生的 |
| 高并发下 cout 带锁 | 很慢，拖慢性能 |
| 没有日志级别 | 无法过滤 DEBUG 信息 |

### 日志要解决什么

1. 所有日志写入文件，程序退出后还能查
2. 每条日志带时间戳、级别、文件名:行号
3. 高并发下不拖慢主流程（异步落盘）

## 2. 第一步：同步日志

### 2.1 整体结构

```cpp
class Logger {
public:
    static Logger& instance();   // 单例
    void init(const char* filename);  // 打开日志文件
    void log(Level level, const char* file, int line, const char* fmt, ...);
private:
    FILE* fp_;
};
```

### 2.2 单例模式

```cpp
static Logger& instance() {
    static Logger inst;  // 局部静态变量，只构造一次
    return inst;
}
```

- 全局只有一个 Logger 实例
- 第一次调用时构造，之后都返回同一个
- 所有地方通过 `Logger::instance()` 获取

### 2.3 变参函数写日志

```cpp
void log(Level level, const char* file, int line, const char* fmt, ...) {
    // 1. 时间戳
    char timebuf[32];
    time_t now = time(nullptr);
    struct tm* tm = localtime(&now);
    strftime(timebuf, sizeof(timebuf), "%Y-%m-%d %H:%M:%S", tm);

    // 2. 级别字符串
    const char* level_str[] = {"DEBUG", "INFO", "WARN", "ERROR"};

    // 3. 写头部
    fprintf(fp_, "[%s] [%s] [%s:%d] ", timebuf, level_str[level], file, line);

    // 4. 写用户内容
    va_list ap;
    va_start(ap, fmt);
    vfprintf(fp_, fmt, ap);
    va_end(ap);

    // 5. 换行 + 刷盘
    fprintf(fp_, "\n");
    fflush(fp_);
}
```

### 2.4 宏包装

```cpp
#define LOG_INFO(fmt, ...) Logger::instance().log(Logger::INFO, __FILE__, __LINE__, fmt, ##__VA_ARGS__)
```

调用：
```cpp
LOG_INFO("服务器启动，端口 %d", 9000);
```

展开后：
```cpp
Logger::instance().log(Logger::INFO, "m6_log.cpp", 70, "服务器启动，端口 %d", 9000);
```

## 3. 第二步：双缓冲异步日志

### 3.1 为什么同步日志慢

同步日志每条都做：
```
fprintf(fp_, ...);  // 写文件
fflush(fp_);         // 立即刷盘 ← 慢！
```

`fflush` 触发 write 系统调用 + 磁盘 IO。高并发下每秒成千上万条日志，全是系统调用和磁盘 IO，CPU 大量花在内核态。

### 3.2 异步日志思路

```
工作线程（写日志）          后台线程（落盘）
     ↓                         
往 current_buffer_ 写          平时阻塞在 cond_.wait()
     ↓                         
current_buffer_ 满了？         
     ↓                         
交换：                         
  current_buffer_ → 待写队列   
  next_buffer_ → current_buffer_
  唤醒后台线程                 
                              后台线程醒过来：
                                把待写队列里的缓冲区批量写文件
                                写完清空，等下一次唤醒
```

**核心**：工作线程只往内存写，不碰文件。后台线程负责批量落盘。

### 3.3 双缓冲数据结构

```cpp
using Buffer = std::vector<char>;

class Logger {
    Buffer current_buffer_;                 // 当前正在写的
    Buffer next_buffer_;                    // 备用的
    std::vector<Buffer> buffers_to_write_;  // 待写队列
    std::mutex mutex_;
    std::condition_variable cond_;
    std::thread backend_thread_;
    bool running_;
};
```

### 3.4 append()：工作线程调用

```cpp
void append(const char* log_line, size_t len) {
    std::lock_guard<std::mutex> lock(mutex_);

    if (current_buffer_.capacity() - current_buffer_.size() >= len) {
        // 缓冲区还够，直接追加
        current_buffer_.insert(current_buffer_.end(), log_line, log_line + len);
    } else {
        // 缓冲区满了：
        buffers_to_write_.push_back(std::move(current_buffer_));  // 满的丢进待写队列
        current_buffer_ = std::move(next_buffer_);               // 备用的顶上
        current_buffer_.insert(current_buffer_.end(), log_line, log_line + len);
        cond_.notify_one();  // 唤醒后台线程
    }
}
```

### 3.5 backend_thread_func()：后台线程

```cpp
void backend_thread_func() {
    while (running_) {
        std::unique_lock<std::mutex> lock(mutex_);
        cond_.wait_for(lock, std::chrono::seconds(3));  // 等3秒或被唤醒

        // 把当前缓冲区也丢进去（即使没满，3秒到了也要刷）
        buffers_to_write_.push_back(std::move(current_buffer_));
        current_buffer_ = std::move(next_buffer_);

        lock.unlock();  // 解锁，写文件不占锁

        // 批量写文件
        for (auto& buf : buffers_to_write_) {
            fwrite(buf.data(), 1, buf.size(), fp_);
            buf.clear();
        }
        fflush(fp_);
        buffers_to_write_.clear();
    }
}
```

### 3.6 为什么 wait_for 3 秒

- 如果一直没有日志，后台线程不会醒，CPU 占用为 0
- 如果日志太少，缓冲区一直不满，数据会一直在内存里不落盘
- 3 秒超时醒一次，把当前缓冲区刷到磁盘，保证日志不会丢太久

### 3.7 优雅退出

```cpp
~Logger() {
    running_ = false;
    cond_.notify_one();           // 唤醒后台线程退出
    if (backend_thread_.joinable()) {
        backend_thread_.join();   // 等后台线程跑完
    }
    // 把剩余缓冲区写文件
    if (current_buffer_.size() > 0) {
        fwrite(current_buffer_.data(), 1, current_buffer_.size(), fp_);
    }
    fflush(fp_);
    if (fp_) fclose(fp_);
}
```

## 4. 第三步：集成到 WebServer

### 4.1 替换 cout

```cpp
// 原来
std::cout << "新的连接, ip=" << inet_ntoa(...) << std::endl;

// 改成
LOG_INFO("新的连接, ip=%s, port=%d", inet_ntoa(...), ntohs(...));
```

### 4.2 .c_str() 的坑

```cpp
// ❌ 错误：std::string 直接传给 %s
LOG_INFO("URL: %s", url);

// ✅ 正确：加 .c_str()
LOG_INFO("URL: %s", url.c_str());
```

`%s` 期望 `const char*`。std::string 是类对象，直接传过去 printf 把它的内存当指针解析，输出乱码。

## 5. 语法点详解

### 5.1 变参函数：va_list 四件套

```cpp
va_list ap;
va_start(ap, fmt);       // ap 指向第一个可变参数
vfprintf(fp_, fmt, ap);  // 按 fmt 格式化输出
va_end(ap);              // 清理
```

- `...` 表示可变参数（数量不定）
- `va_start(ap, fmt)`：ap 指向 fmt 后面的第一个参数
- `vfprintf`：接受 va_list 而不是 ... 的 printf 版本
- `va_end`：清理

### 5.2 宏的可变参数：##__VA_ARGS__

```cpp
#define LOG_INFO(fmt, ...) log(..., fmt, ##__VA_ARGS__)
```

- `...` 是宏的可变参数
- `__VA_ARGS__` 代表所有可变参数
- `##` 的作用：如果 __VA_ARGS__ 为空，把前面的逗号也删掉

```cpp
LOG_INFO("hello")       // → log(..., "hello")     （逗号被删了）
LOG_INFO("fd=%d", 6)   // → log(..., "fd=%d", 6)
```

### 5.3 __FILE__ 和 __LINE__

预处理器在编译阶段自动替换：
- `__FILE__` → 当前文件名（字符串）
- `__LINE__` → 当前行号（整数）

用宏包装才能拿到调用者的文件和行号，函数做不到。

### 5.4 std::move

```cpp
buffers_to_write_.push_back(std::move(current_buffer_));
```

- `std::move` 本身什么都不做，只是把左值转成右值引用
- 真正的"移动"在 vector 的移动构造函数里：偷指针，O(1)
- 拷贝 vector 要复制全部数据，O(n)
- 移动 vector 只转移几个指针，瞬间完成

### 5.5 condition_variable

```cpp
cond_.wait_for(lock, 3s);  // 阻塞，被 notify 或超时才醒
cond_.notify_one();         // 唤醒一个等待者
```

- 后台线程平时阻塞，不占 CPU
- 工作线程写完数据后 notify，后台线程醒过来写文件
- wait_for 有超时，3 秒没日志也会醒

### 5.6 snprintf / vsnprintf

```cpp
snprintf(buf, sizeof(buf), "[%s] ", timebuf);
vsnprintf(buf + len, sizeof(buf) - len, fmt, ap);
```

- 安全的 sprintf，第二个参数是缓冲区大小，不会越界
- vsnprintf 和 vfprintf 类似，但写到字符串缓冲区而不是文件

### 5.7 using 类型别名

```cpp
using Buffer = std::vector<char>;
```

等价于 `typedef std::vector<char> Buffer;`，但更直观。

## 6. 踩坑汇总

### 坑1：std::string 传给 %s 导致乱码

- **现象**：日志里 URL 和文件路径全是乱码
- **原因**：`LOG_INFO("URL=%s", url)`，url 是 std::string，不是 const char*
- **修复**：`url.c_str()`

### 坑2：double free or corruption

- **现象**：高并发压测时 `double free or corruption (!prev)`，Aborted
- **原因**：close_callback 的任务里，当 ch 已被 delete 时，执行了 `delete req`。但 req 已经被 handle_read 的关闭分支 delete 过了，重复 free
- **竞态时序**：
  ```
  1. 工作线程 close_callback → runInLoop(task) 入队
  2. 主线程 handle_read → recv=0 → delete req → delete ch
  3. 主线程执行 task → ch 已无效 → delete req（重复！）
  ```
- **修复**：task 里 ch 无效时直接 return，不 delete req（req 已被关闭分支 delete）

### 坑3：段错误 / 越界断言失败

- **现象**：高并发压测时 Segmentation fault 或 `Assertion '__n < this->size()' failed`
- **原因**：大量短连接同时断开，竞态条件导致访问了已 delete 的 ch，ch->getfd() 返回垃圾值，channels_[垃圾值] 越界
- **修复**：close_connection 和 handle_expired 里加 fd 范围检查

### 坑4：编译漏了 -pthread

- **现象**：undefined reference to pthread_create 之类
- **原因**：用了 std::thread、std::mutex，必须加 -pthread
- **修复**：`g++ -Wall -g m6_log.cpp -o m6.log -pthread`

## 7. 面试问答

### Q1：为什么用异步日志而不是同步日志？

答：同步日志每条都 fflush，触发 write 系统调用和磁盘 IO。高并发下每秒成千上万条日志，系统调用开销很大。异步日志把日志写到内存缓冲区，后台线程批量写文件，工作线程只碰内存，性能提升明显。

### Q2：双缓冲是什么？为什么要两个缓冲区？

答：一个 current_buffer_ 给工作线程写，一个 next_buffer_ 备用。current_buffer_ 满了，直接把满的交给后台线程写，next_buffer_ 顶上。这样工作线程不用等后台线程写完，O(1) 切换。如果只有一个缓冲区，工作线程写满后必须等后台线程写完才能继续写，会阻塞。

### Q3：为什么用 condition_variable？

答：后台线程平时阻塞，不占 CPU。工作线程写完日志后 notify，后台线程才醒过来写文件。wait_for 设了 3 秒超时，防止日志太少时数据一直在内存里不落盘。

### Q4：std::move 做了什么？

答：std::move 本身不移动任何数据，只是把左值转成右值引用。真正的移动在 vector 的移动构造函数里：把内部指针偷过来，源 vector 置空，O(1)。比拷贝 O(n) 快得多。

### Q5：##__VA_ARGS__ 是什么？

答：宏的可变参数。`...` 表示参数数量不定，`__VA_ARGS__` 代表所有可变参数。`##` 的作用是：如果没有可变参数，把前面的逗号也删掉，避免语法错误。

### Q6：__FILE__ 和 __LINE__ 怎么拿到的？

答：预处理器在编译阶段自动替换。源码里写的 `__FILE__` 在预处理后变成实际的文件名，`__LINE__` 变成实际行号。用宏包装才能拿到调用者的位置，函数做不到。

### Q7：日志在多线程下安全吗？

答：安全。append() 里用 mutex_ 加锁，多个工作线程同时写日志不会竞争。后台线程写文件时先把缓冲区 swap 出来，解锁后再写，不占锁太久。
