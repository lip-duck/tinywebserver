## 1. 环境搭建

### 安装

```bash
sudo apt install mysql-server libmysqlclient-dev
```

- `mysql-server`：MySQL 服务端
- `libmysqlclient-dev`：C API 头文件和库

### 启动服务

```bash
sudo service mysql start
```

### 建库建表

```sql
CREATE DATABASE webserver DEFAULT CHARACTER SET utf8mb4;
CREATE USER 'lip'@'localhost' IDENTIFIED BY '123456';
GRANT ALL PRIVILEGES ON webserver.* TO 'lip'@'localhost';
FLUSH PRIVILEGES;

USE webserver;
CREATE TABLE user (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    password VARCHAR(50) NOT NULL
);
```

### 编译命令

```bash
g++ -Wall -g m7_mysql.cpp -o m7.mysql -pthread `mysql_config --cflags --libs`
```

`mysql_config --cflags --libs` 自动找头文件路径和库文件，不用手动写 `-I` 和 `-l`。

## 2. 第一步：MySQL C API 基础

### 核心函数调用流程

```
mysql_init()
    ↓
mysql_real_connect()  ← 连接数据库
    ↓
mysql_query()         ← 执行 SQL
    ↓
SELECT?
    ├─ 是 → mysql_store_result() → mysql_fetch_row() → mysql_free_result()
    └─ 否 → mysql_affected_rows()
    ↓
mysql_close()
```

### 2.1 mysql_init()

```cpp
MYSQL* conn = mysql_init(nullptr);
```
- 分配并初始化 MYSQL 对象
- 传 nullptr 让库自己分配内存

### 2.2 mysql_real_connect()

```cpp
mysql_real_connect(conn, "localhost", "lip", "123456", "webserver", 3306, nullptr, 0);
```
- 连接数据库，失败返回 NULL
- 参数：句柄、主机、用户、密码、数据库名、端口、socket、标志
- 错误信息用 `mysql_error(conn)` 获取

### 2.3 mysql_query()

```cpp
mysql_query(conn, "INSERT INTO user ...");
```
- 返回 0 成功，非 0 失败
- SQL 里不加引号和分号
- **注意：直接拼接字符串有 SQL 注入风险**

### 2.4 mysql_affected_rows()

```cpp
mysql_affected_rows(conn);  // 返回影响行数
```
- INSERT/UPDATE/DELETE 后看影响了多少行
- printf 用 `%lld`

### 2.5 结果集三件套

```cpp
MYSQL_RES* res = mysql_store_result(conn);  // 把结果全部读到内存
MYSQL_ROW row = mysql_fetch_row(res);      // 取下一行
mysql_free_result(res);                      // 释放结果集
```

- `mysql_store_result()`：一次性读全部结果到客户端内存
- `mysql_fetch_row()`：返回 `char*` 数组，所有值都是字符串（INT 也要 atoi 转）
- 值可能为 NULL，row[i] 是 0（空指针），要判断
- `mysql_free_result(res)` 必须调，否则内存泄漏

### 2.6 完整测试代码

```cpp
#include <mysql/mysql.h>
#include <cstdio>

int main() {
    MYSQL* conn = mysql_init(nullptr);
    if (!mysql_real_connect(conn, "localhost", "lip", "123456", "webserver", 3306, nullptr, 0)) {
        printf("连接失败: %s\n", mysql_error(conn));
        return 1;
    }

    // 插入
    mysql_query(conn, "INSERT INTO user (username, password) VALUES ('zhangsan', '123456')");
    printf("影响行数: %lld\n", mysql_affected_rows(conn));

    // 查询
    mysql_query(conn, "SELECT id, username, password FROM user");
    MYSQL_RES* res = mysql_store_result(conn);
    MYSQL_ROW row;
    while ((row = mysql_fetch_row(res))) {
        printf("id=%s user=%s pass=%s\n", row[0], row[1], row[2]);
    }
    mysql_free_result(res);
    mysql_close(conn);
}
```

## 3. 第二步：连接池

### 为什么需要连接池

每次请求新建连接：
```
TCP三次握手 + MySQL认证 + 分配内存 ≈ 几毫秒
高并发下几千次连接建立/断开，CPU 全花在握手和认证上
```

连接池：启动时预建 N 个连接，请求来了取一个，用完放回去。

### 3.1 整体结构

```cpp
class ConnPool {
public:
    static ConnPool& instance();           // 单例
    MYSQL* get_conn();                      // 取连接
    void release_conn(MYSQL* conn);        // 归还连接
    void init(host, user, passwd, db, 8);  // 初始化池大小
private:
    std::queue<MYSQL*> queue_;
    std::mutex mutex_;
    std::condition_variable cond_;
};
```

### 3.2 get_conn() — 取连接

```cpp
MYSQL* get_conn() {
    std::unique_lock<std::mutex> lock(mutex_);
    while (queue_.empty()) {
        if (cond_.wait_for(lock, 1s) == timeout) return nullptr;
    }
    MYSQL* conn = queue_.front();
    queue_.pop();
    lock.unlock();

    // 检查连接是否活着
    if (mysql_ping(conn)) {
        mysql_close(conn);
        conn = create_conn();  // 死了就重连
    }
    return conn;
}
```

### 3.3 release_conn() — 归还连接

```cpp
void release_conn(MYSQL* conn) {
    {
        std::lock_guard<std::mutex> lock(mutex_);
        queue_.push(conn);
    }
    cond_.notify_one();  // 叫醒等待的线程
}
```

### 3.4 mysql_ping()

```cpp
mysql_ping(conn);  // 返回 0 表示连接活着
```
- MySQL 服务器会自动断开空闲连接（默认 8 小时）
- 从池里取连接时 ping 一下，断了就重连

### 3.5 ConnGuard RAII

```cpp
class ConnGuard {
public:
    explicit ConnGuard(MYSQL* conn) : conn_(conn) {}
    ~ConnGuard() { if (conn_) ConnPool::instance().release_conn(conn_); }
    MYSQL* get() { return conn_; }
private:
    MYSQL* conn_;
};
```

用法：
```cpp
{
    ConnGuard guard(pool.get_conn());
    // 用 conn 查询
}  // 离开作用域自动归还，不用手动 release
```

## 4. 第三步：注册登录接口

### 4.1 HTTP POST 请求格式

```
POST /register HTTP/1.1
Host: localhost:9000
Content-Length: 35
Content-Type: application/x-www-form-urlencoded

username=testuser&password=123456
```

- body 在 `\r\n\r\n` 后面
- 格式：`key=value&key=value`

### 4.2 注册逻辑

```cpp
if (method == "POST" && url == "/register") {
    // 1. 解析 body
    std::string body = req->body_;
    // 找 username=xxx&password=xxx

    // 2. 查用户名是否已存在
    ConnGuard guard(pool.get_conn());
    snprintf(sql, "SELECT id FROM user WHERE username='%s'", username.c_str());
    mysql_query(conn, sql);
    res = mysql_store_result(conn);

    if (mysql_num_rows(res) > 0) {
        // 用户名已存在 → 409
    } else {
        // 插入新用户 → 200
        snprintf(sql, "INSERT INTO user VALUES ('%s','%s')", ...);
    }
    mysql_free_result(res);
}
```

### 4.3 登录逻辑

```cpp
if (method == "POST" && url == "/login") {
    // 1. 解析 body
    // 2. 查密码
    snprintf(sql, "SELECT password FROM user WHERE username='%s'", ...);
    mysql_query(conn, sql);
    res = mysql_store_result(conn);
    row = mysql_fetch_row(res);

    if (row && password == row[0]) {
        // 密码正确 → 200
    } else {
        // 用户不存在或密码错误 → 401
    }
    mysql_free_result(res);
}
```

## 5. 语法点详解

### 5.1 单例模式：=default 和 =delete

```cpp
private:
    ConnPool() = default;                              // 私有构造，外面不能 new
    ConnPool(const ConnPool&) = delete;                 // 禁止拷贝构造
    ConnPool& operator=(const ConnPool&) = delete;      // 禁止拷贝赋值
```

- `= default`：让编译器生成默认构造函数
- `= delete`：禁止调用，编译报错
- 单例只允许通过 `instance()` 获取，不能 new 或拷贝

### 5.2 condition_variable：wait_for 和 notify_one

```cpp
// 等待
cond_.wait_for(lock, std::chrono::seconds(1));
// 返回 std::cv_status::no_timeout（被叫醒）或 std::cv_status::timeout（超时）
```

```cpp
// 唤醒
cond_.notify_one();   // 叫醒一个等待者
cond_.notify_all();   // 叫醒所有等待者
```

**为什么用 while 不用 if：**
```cpp
while (queue_.empty()) {     // 每次醒了都重新检查
    cond_.wait_for(lock, 1s);
}
```
- 虚假唤醒：操作系统可能在没有 notify 的情况下叫醒线程
- 用 while 确保醒了后再检查一次条件

### 5.3 RAII：ConnGuard 析构时机

```cpp
{
    ConnGuard guard(conn);
    // 用 conn
}  // 离开作用域，guard 析构，自动归还连接
```

析构时机：
- 代码块 `}` 结束
- 函数 return
- for 循环每轮结束
- 异常抛出

### 5.4 snprintf 拼 SQL

```cpp
char sql[512];
snprintf(sql, sizeof(sql), "SELECT * FROM user WHERE username='%s'", username.c_str());
```
- 安全的 sprintf，第二个参数是缓冲区大小，不会越界
- **SQL 注入风险**：直接拼接字符串，username 如果是 `' OR 1=1 --` 就被注入了
- 生产环境应该用预处理语句（mysql_stmt_prepare）

### 5.5 std::chrono

```cpp
std::chrono::seconds(1)       // 1 秒
std::chrono::milliseconds(500) // 500 毫秒
```
- 类型安全，不能传裸整数
- C++14 字面量：`1s`、`500ms`

## 6. 踩坑汇总

### 坑1：Content-Length 和 Content-Type 写反了

- **现象**：响应头混乱，浏览器解析失败
- **代码**：
  ```cpp
  response += "Content-Length: text/plain\r\n";  // ❌
  response += "Content-Type: 25\r\n";            // ❌
  ```
- **修复**：
  ```cpp
  response += "Content-Type: text/plain\r\n";   // ✅
  response += "Content-Length: 25\r\n";          // ✅
  ```

### 坑2：keep_alive = false 强制短连接

- **现象**：每次发完请求连接就断
- **代码**：`keep_alive = false;  // 调试时加的`
- **修复**：删掉这行，走正常 keep-alive 判断

### 坑3：close_callback 检查挡住正常流程

- **现象**：POST 请求发完响应后连接就断，不能连续发多个请求
- **根因**：
  ```cpp
  // handle_read 里 parse 成功后：
  g_loop->deletechannel(ch);  // channels_[fd] = nullptr

  // close_callback 的 task 里：
  if (g_loop->get_channel(fd) != ch) {
      return;  // get_channel(fd)=nullptr, ch=有效指针, nullptr!=ch → true → return
  }
  ```
  handle_read 已经把 channels_[fd] 设为 nullptr，task 里检查 nullptr != ch 为 true，直接 return，不重新注册读事件。
- **修复**：注释掉这个检查，直接执行重新注册逻辑

### 坑4：Content-Length 字节数算错

- **中文 UTF-8 每个汉字 3 字节**
- "注册成功" = 4×3 = 12 字节
- "用户名已存在" = 6×3 = 18 字节
- "用户名或密码错误" = 8×3 = 24 字节

### 坑5：Content-Length 后少 \r\n

- **现象**：响应头连在一起，解析错误
- **修复**：每个头后面都要有 `\r\n`，最后一个头后再加 `\r\n` 表示头结束

### 坑6：编译漏了 mysql_config

- **现象**：undefined reference to mysql_init 等
- **修复**：`g++ ... `mysql_config --cflags --libs``

## 7. 面试问答

### Q1：为什么需要数据库连接池？

答：每次 HTTP 请求新建 MySQL 连接要经过 TCP 三次握手 + MySQL 认证 + 分配内存，开销很大。高并发下几千次连接建立/断开，CPU 全花在握手认证上。连接池启动时预建 N 个连接，请求来了取一个用完放回，复用连接，省去反复建连开销。

### Q2：连接池怎么保证线程安全？

答：用 mutex 保护队列。get_conn 时加锁取连接，release_conn 时加锁放连接。条件变量处理池空时的等待。

### Q3：连接池里的连接断了怎么办？

答：get_conn 时调 mysql_ping(conn) 检查连接是否活着。如果返回非 0（连接断了），close 旧连接，create_conn() 新建一个。MySQL 服务器默认会断开空闲 8 小时以上的连接，ping 是必须的。

### Q4：RAII 是什么？ConnGuard 怎么做的？

答：Resource Acquisition Is Initialization，资源获取即初始化。把资源（数据库连接）绑定到对象生命周期上，构造时获取资源，析构时自动释放资源。ConnGuard 构造时拿连接，析构时自动调 release_conn 归还，即使中间 return 或抛异常也不会泄漏连接。

### Q5：什么是 SQL 注入？怎么防？

答：直接拼接用户输入到 SQL 字符串里。比如 username = `' OR 1=1 --`，拼接后 SQL 变成 `SELECT * FROM user WHERE username='' OR 1=1 --'`，绕过验证。防法：用预处理语句（mysql_stmt_prepare），参数和 SQL 分开，不拼接。

### Q6：单例模式为什么要 =delete？

答：防止别人拷贝连接池。如果不 delete，别人可以 `ConnPool b = ConnPool::instance()`，复制出第二个连接池，同一个数据库连接被两个池管理，出大问题。=delete 让编译器报错，明确禁止。

### Q7：wait_for 和 wait 有什么区别？

答：wait 一直等，死等到天荒地老。wait_for 最多等指定时间，超时也返回。用 wait_for 防止池里连接全坏了时线程永远卡住。返回值 std::cv_status::no_timeout 表示被叫醒，timeout 表示超时。

### Q8：为什么等待条件用 while 不用 if？

答：虚假唤醒。操作系统可能在没有 notify 的情况下叫醒线程。用 while 确保醒了后再检查一次队列是否真的有连接，if 的话只检查一次就往下走，队列可能还是空的。
