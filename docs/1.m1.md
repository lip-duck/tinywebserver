# M1 网络 IO 演进 —— 完整学习笔记

> 对应零声课程 2.1.1，TinyWebServer 的网络 IO 基础。
> 目标：从最原始的阻塞式 TCP 服务器，逐步演进到 epoll 高性能 IO 多路复用，理解每个版本解决的问题和优缺点。

---

## 一、M1 概述

### 1.1 五个版本的演进路线

| 版本 | 名称 | 核心机制 | 解决的问题 | 并发能力 |
|------|------|---------|-----------|---------|
| 1 | 阻塞式 | accept/recv/send 全部阻塞 | 入门，理解 TCP 编程 | 1（串行） |
| 2 | 多线程 | 每连接一个线程 | 阻塞 accept 不影响其他连接 | 几百（线程开销大） |
| 3 | select | IO 多路复用，fd_set | 一个线程管理多个连接 | 1024（FD_SETSIZE 限制） |
| 4 | poll | IO 多路复用，pollfd 数组 | 去掉 1024 限制 | 几千（数组遍历开销） |
| 5 | epoll | 事件驱动，红黑树+就绪链表 | 只处理就绪事件，O(1) 监听 | 百万级 |

### 1.2 演进逻辑

```
阻塞式：一个连接卡住，所有连接都等
   ↓ 用线程隔离阻塞
多线程：每连接一个线程，但线程创建/销毁/切换开销大
   ↓ 用一个线程管理多个连接（IO 多路复用）
select：fd_set 位图，1024 限制，每次遍历全部 fd
   ↓ 去掉 1024 限制
poll：pollfd 数组，无数量限制，但仍要遍历全部 fd
   ↓ 只返回就绪的 fd，不遍历全部
epoll：事件驱动，只处理就绪事件，高性能
```

## 二、基础函数详解（所有版本共用）

### 2.1 socket() —— 创建套接字

```cpp
int socket(int domain, int type, int protocol);
```

**返回值**：成功返回文件描述符 fd（非负整数），失败返回 -1。

| 参数 | 含义 | 常用值 |
|------|------|--------|
| `domain` | 协议族（地址族） | `AF_INET`（IPv4） |
| `type` | 套接字类型 | `SOCK_STREAM`（TCP）、`SOCK_DGRAM`（UDP） |
| `protocol` | 具体协议 | 一般填 0，系统自动选择 |

- `AF_INET + SOCK_STREAM` → 自动选 TCP
- `AF_INET + SOCK_DGRAM` → 自动选 UDP

### 2.2 bind() —— 绑定地址和端口

```cpp
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

把 socket 和一个 IP 地址+端口绑定。服务端必须 bind，客户端一般不 bind（系统自动分配端口）。

**常见错误**：`bind: Address already in use` —— 端口被占用，换端口或杀掉旧进程。

### 2.3 listen() —— 开始监听

```cpp
int listen(int sockfd, int backlog);
```

- `backlog`：已完成三次握手但未被 accept 的连接队列长度。一般写 5 或 `SOMAXCONN`（系统最大值，通常 128）。
- 调用 listen 后，socket 从"主动"变为"被动"，可以接受连接了。

### 2.4 accept() —— 接受连接

```cpp
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
```

**返回值**：成功返回新的连接 fd（connfd），失败返回 -1。

- `sockfd`：监听 fd（listenfd）
- `addr`：输出参数，存放客户端的 IP 和端口
- `addrlen`：输入输出参数，传入缓冲区大小，返回实际地址长度

> ⚠️ **第三个参数是 `socklen_t*`，不是 `int*`**！类型不匹配会有隐蔽 bug。

```cpp
struct sockaddr_in client_addr;
socklen_t len = sizeof(client_addr);  // ✅ 用 socklen_t
int connfd = accept(listenfd, (struct sockaddr*)&client_addr, &len);
```

### 2.5 recv() —— 接收数据

```cpp
ssize_t recv(int sockfd, void *buf, size_t len, int flags);
```

**返回值 `ssize_t`（有符号整数）**：

| 返回值 | 含义 |
|--------|------|
| > 0 | 成功，返回读到的字节数 |
| 0 | **对端正常关闭连接（TCP FIN）**，不是错误！ |
| -1 | 出错，errno 有意义 |

- `flags` 一般填 0，此时行为等价于 `read()`
- 非阻塞模式下，缓冲区空时返回 -1，errno = `EAGAIN`（或 `EWOULDBLOCK`）

### 2.6 send() —— 发送数据

```cpp
ssize_t send(int sockfd, const void *buf, size_t len, int flags);
```

**返回值**：成功返回实际发送的字节数（可能小于 len，因为发送缓冲区满了），失败返回 -1。

> ⚠️ 非阻塞模式下，send 可能只发了一部分，需要循环发送直到全部发完。

### 2.7 close() —— 关闭套接字

```cpp
int close(int fd);
```

关闭文件描述符，释放资源。关闭后 fd 可以被重新分配给新的 socket。

> ⚠️ 关闭顺序：先从 epoll/select 中移除，再 close(fd)，最后释放关联的对象内存。

### 2.8 perror() —— 打印错误信息

```cpp
#include <stdio.h>
void perror(const char *s);
```

当系统调用返回 -1 时，操作系统把错误编号存入全局变量 `errno`。`perror("自定义字符串")` 会先打印自定义字符串，再冒号，再打印 errno 对应的人类可读错误文本。

```cpp
if (listenfd == -1) {
    perror("socket");  // 输出：socket: Address already in use
    return -1;
}
```

**等价写法**：
```cpp
printf("socket: %s\n", strerror(errno));  // strerror 把 errno 转成字符串，不直接打印
```

**重点规则**：
1. 只有系统调用返回 -1，errno 才有意义；成功时 errno 值未定义
2. errno 会被后续系统调用覆盖，出错后立刻调用 perror
3. 常见报错：`Address already in use`（端口占用）、`Bad file descriptor`（fd 已关闭）、`Cannot assign requested address`（源端口耗尽）

### 2.9 sockaddr_in —— IPv4 地址结构体

```cpp
#include <netinet/in.h>
#include <arpa/inet.h>

struct sockaddr_in {
    sa_family_t    sin_family;   // 地址族，固定 AF_INET
    in_port_t      sin_port;     // 端口号，必须网络字节序 htons()
    struct in_addr sin_addr;     // IPv4 地址结构体
    unsigned char  sin_zero[8];  // 填充字节，补到和 sockaddr 对齐，填0
};

struct in_addr {
    uint32_t s_addr;   // IPv4 地址，网络字节序（大端）
};
```

**服务端初始化（bind 用）**：
```cpp
struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_port = htons(9000);                    // 端口转网络字节序
addr.sin_addr.s_addr = htonl(INADDR_ANY);       // 监听所有网卡 0.0.0.0
```

**客户端初始化（connect 用）**：
```cpp
struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_port = htons(9000);
addr.sin_addr.s_addr = inet_addr("127.0.0.1");  // 字符串IP转网络字节序
```

**强制类型转换**：`bind/connect/accept` 的第二个参数是 `struct sockaddr*`（通用地址），不能直接传 `sockaddr_in*`，必须强转：
```cpp
bind(listenfd, (struct sockaddr*)&addr, sizeof(addr));
```

### 2.10 字节序转换（高频踩坑）

CPU 内部是**小端序**（主机字节序），网络传输规定**大端序**（网络字节序）。端口和 IP 存入 `sockaddr_in` 必须转大端！

| 函数 | 作用 | 用途 |
|------|------|------|
| `htons()` | host to network short（16位） | 端口号 |
| `htonl()` | host to network long（32位） | IP 整数 |
| `ntohs()` | network to host short（16位） | 把读出来的端口转回主机序打印 |
| `ntohl()` | network to host long（32位） | IP 转回主机序 |

**IP 字符串和网络字节序互转**：
```cpp
// "127.0.0.1" → 网络字节序 uint32_t
addr.sin_addr.s_addr = inet_addr("127.0.0.1");

// 网络字节序 → 打印字符串 IP
printf("client ip = %s\n", inet_ntoa(client_addr.sin_addr));
```

**INADDR_ANY**：`htonl(INADDR_ANY)` 等价于 `htonl(0)`，代表 `0.0.0.0`，监听本机所有网卡。服务端常用，客户端不要用（客户端要写明确目标 IP）。

### 2.11 socklen_t

```cpp
typedef unsigned int socklen_t;  // 无符号整数
```

专门用于 socket API，存放地址结构体的字节大小。`accept/getsockname/getpeername` 的最后一个参数是 `socklen_t*`，不是 `int*`。

### 2.12 fcntl() —— 设置非阻塞

```cpp
#include <fcntl.h>
int fcntl(int fd, int cmd, ...);
```

**设置非阻塞 socket**：
```cpp
int flags = fcntl(fd, F_GETFL, 0);      // 获取当前标志
flags |= O_NONBLOCK;                       // 加上非阻塞标志
fcntl(fd, F_SETFL, flags);                 // 设置回去
```

非阻塞模式下，`accept/recv/send` 不会阻塞，缓冲区空/满时立即返回 -1，errno = `EAGAIN`。

> ⚠️ IO 多路复用（select/poll/epoll）配合非阻塞 socket 使用，必须读到 `EAGAIN` 才算读完。

### 2.13 getpeername() —— 获取对端地址

```cpp
int getpeername(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
```

通过连接 fd 获取对端（客户端）的 IP 和端口。**必须在 close(fd) 之前调用**，关闭后 fd 无效。

```cpp
struct sockaddr_in peer_addr;
socklen_t peer_len = sizeof(peer_addr);
getpeername(fd, (struct sockaddr*)&peer_addr, &peer_len);
std::cout << "客户端ip：" << inet_ntoa(peer_addr.sin_addr) << std::endl;
std::cout << "客户端端口：" << ntohs(peer_addr.sin_port) << std::endl;
```

> 注意：不能用 connfd 直接得到地址，connfd 只是一个整数 fd，必须用 `getpeername` 或在 accept 时保存 `client_addr`。

### 2.14 编译命令

```bash
g++ -Wall -g server.cpp -o server    # C++ 编译
gcc -Wall -g client.c -o client       # C 编译
```

- `-Wall`：打开全部基础警告
- `-g`：加入调试信息，供 gdb 调试
- 用 `std::thread` 时必须加 `-pthread`：`g++ -std=c++11 -pthread server.cpp -o server`

> ⚠️ 修改代码后必须重新编译，否则运行的是旧程序。`-o` 后面的输出名不要和 `.cpp` 重名（会覆盖源文件）。

## 三、版本1：阻塞式 TCP 回显服务器

### 3.1 目标

最原始的 TCP 服务器：接受一个连接，接收数据，原样发回去（回显），连接关闭后再接受下一个。

### 3.2 代码模板

```cpp
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <stdio.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

int main() {
    // 1. 创建 socket
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    if (listenfd == -1) { perror("socket"); return -1; }

    // 2. 绑定地址和端口
    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_port = htons(9000);
    addr.sin_addr.s_addr = htonl(INADDR_ANY);
    if (bind(listenfd, (struct sockaddr*)&addr, sizeof(addr)) == -1) {
        perror("bind"); return 1;
    }

    // 3. 开始监听
    if (listen(listenfd, 5) == -1) { perror("listen"); return 1; }
    std::cout << "阻塞服务器启动，监听 9000 端口" << std::endl;

    // 4. 主循环
    while (1) {
        struct sockaddr_in client_addr;
        socklen_t len = sizeof(client_addr);
        // 阻塞点1：accept，没有客户端连接就一直卡住
        int connfd = accept(listenfd, (struct sockaddr*)&client_addr, &len);
        if (connfd == -1) { perror("accept"); continue; }
        std::cout << "客户端ip：" << inet_ntoa(client_addr.sin_addr) << std::endl;
        std::cout << "端口：" << ntohs(client_addr.sin_port) << std::endl;

        char buf[1024];
        while (true) {
            memset(buf, 0, sizeof(buf));
            // 阻塞点2：recv，客户端不发数据就一直卡住
            int n = recv(connfd, buf, sizeof(buf), 0);
            if (n <= 0) break;
            // 阻塞点3：send，发送缓冲区满时可能阻塞
            send(connfd, buf, n, 0);
        }
        close(connfd);
        std::cout << "连接关闭" << std::endl;
    }
    close(listenfd);
    return 0;
}
```

### 3.3 三个阻塞点

| 阻塞点 | 函数 | 阻塞原因 |
|--------|------|---------|
| 1 | `accept()` | 没有客户端连接时，一直等 |
| 2 | `recv()` | 客户端不发数据时，一直等 |
| 3 | `send()` | 发送缓冲区满时，一直等 |

**核心问题**：一个连接卡在 recv（客户端不发数据），整个服务器就卡住了，其他连接无法 accept。这就是"一连接卡住，所有连接都等"。

### 3.4 测试方法

```bash
# 终端1：启动服务器
./m1

# 终端2：用 telnet 或 nc 连接
telnet 127.0.0.1 9000
# 输入任意文字，服务器原样返回
```

### 3.5 优缺点

| 优点 | 缺点 |
|------|------|
| 代码最简单，适合入门 | 串行处理，一次只能服务一个连接 |
| 没有并发概念 | 一个连接阻塞，所有连接等待 |
| | 无法应对高并发 |

## 四、版本2：多线程版本（一连接一线程）

### 4.1 目标

每个新连接创建一个独立线程处理，主线程只负责 accept。这样一个连接卡在 recv 不会影响其他连接。

### 4.2 std::thread 基础

```cpp
#include <thread>

void worker(int id) {
    std::cout << "线程 " << id << " 工作中" << std::endl;
}

int main() {
    std::thread t(worker, 1);  // 创建线程，执行 worker(1)
    t.join();                   // 主线程等待 t 结束
    return 0;
}
```

**join vs detach**：

| 方式 | 作用 | 特点 |
|------|------|------|
| `t.join()` | 主线程阻塞等待子线程结束 | 安全，能拿到执行结果 |
| `t.detach()` | 子线程分离，主线程不等 | 后台运行，不能再 join |

> ⚠️ 必须二选一，什么都不做就析构会导致 `std::terminate` 崩溃。

### 4.3 代码模板

```cpp
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <stdio.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <thread>

void client_thread(int clientfd) {
    char buf[1024];
    while (true) {
        memset(buf, 0, sizeof(buf));
        int n = recv(clientfd, buf, sizeof(buf), 0);
        if (n <= 0) break;
        send(clientfd, buf, n, 0);
    }
    close(clientfd);
    std::cout << "连接关闭" << std::endl;
}

int main() {
    // socket/bind/listen 同版本1，省略...

    while (1) {
        struct sockaddr_in client_addr;
        socklen_t len = sizeof(client_addr);
        int connfd = accept(listenfd, (struct sockaddr*)&client_addr, &len);
        if (connfd == -1) { perror("accept"); continue; }

        // 每个连接创建一个线程
        std::thread t(client_thread, connfd);
        t.detach();  // 分离，主线程不等待
    }
    close(listenfd);
    return 0;
}
```

### 4.4 优缺点

| 优点 | 缺点 |
|------|------|
| 一个连接阻塞不影响其他连接 | 每连接一个线程，高并发下线程数爆炸 |
| 编程模型简单 | 线程创建/销毁开销大 |
| | 线程上下文切换频繁 |
| | 内存占用高（每个线程栈默认 8MB） |
| | 几百连接后性能急剧下降 |

**为什么需要 IO 多路复用**：多线程用"线程数量"换并发，但线程本身有开销。IO 多路复用用"一个线程管理多个 fd"换并发，没有线程开销。

## 五、版本3：select 多路复用

### 5.1 目标

用一个线程同时管理多个 fd，哪个 fd 有数据就处理哪个，没有数据就阻塞等待。不需要为每个连接创建线程。

### 5.2 select 函数详解

```cpp
#include <sys/select.h>
int select(int nfds, fd_set *readfds, fd_set *writefds,
           fd_set *exceptfds, struct timeval *timeout);
```

| 参数 | 含义 |
|------|------|
| `nfds` | 监听的最大 fd + 1（不是 fd 数量！） |
| `readfds` | 要监听读事件的 fd 集合 |
| `writefds` | 要监听写事件的 fd 集合（一般 NULL） |
| `exceptfds` | 要监听异常事件的 fd 集合（一般 NULL） |
| `timeout` | 超时时间，NULL 表示永久阻塞 |

**返回值**：就绪的 fd 总数，超时返回 0，出错返回 -1。

> ⚠️ select 会**修改传入的 fd_set**（只保留就绪的 fd），所以每次调用前必须重新拷贝一份。

### 5.3 fd_set 操作宏

```cpp
fd_set rfds;
FD_ZERO(&rfds);              // 清空集合
FD_SET(fd, &rfds);           // 把 fd 加入集合
FD_CLR(fd, &rfds);           // 把 fd 从集合移除
FD_ISSET(fd, &rfds);         // 判断 fd 是否在集合中（是否就绪）
```

`fd_set` 本质是一个位图，每个 bit 代表一个 fd。**大小固定为 FD_SETSIZE（通常 1024）**，fd 超过 1023 就无法监听。

### 5.4 代码模板

```cpp
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <stdio.h>
#include <sys/socket.h>
#include <sys/select.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <fcntl.h>
#include <errno.h>

int main() {
    // socket/bind/listen 同版本1，省略...

    fd_set rfds;              // 要监听的 fd 集合（主集合）
    FD_ZERO(&rfds);
    FD_SET(listenfd, &rfds); // 把监听 fd 加入
    int maxfd = listenfd;     // 记录最大 fd

    while (1) {
        fd_set rset = rfds;   // ⚠️ 每次循环重新拷贝！select 会修改 rset
        int nready = select(maxfd + 1, &rset, NULL, NULL, NULL);
        if (nready == -1) { perror("select"); break; }

        // 检查监听 fd 是否就绪（有新连接）
        if (FD_ISSET(listenfd, &rset)) {
            struct sockaddr_in client_addr;
            socklen_t len = sizeof(client_addr);
            int connfd = accept(listenfd, (struct sockaddr*)&client_addr, &len);
            if (connfd == -1) { perror("accept"); continue; }

            // 设置非阻塞
            int flags = fcntl(connfd, F_GETFL, 0);
            flags |= O_NONBLOCK;
            fcntl(connfd, F_SETFL, flags);

            FD_SET(connfd, &rfds);  // 加入主集合
            if (connfd > maxfd) maxfd = connfd;
        }

        // 检查所有客户端 fd 是否就绪（有数据）
        for (int fd = listenfd + 1; fd <= maxfd; fd++) {
            if (FD_ISSET(fd, &rset)) {
                char buf[1024];
                while (1) {
                    memset(buf, 0, sizeof(buf));
                    int n = recv(fd, buf, sizeof(buf), 0);
                    if (n == 0) {
                        // 客户端断开
                        FD_CLR(fd, &rfds);
                        close(fd);
                        break;
                    } else if (n < 0) {
                        if (errno == EAGAIN) break;  // 读完了
                        perror("recv");
                        FD_CLR(fd, &rfds);
                        close(fd);
                        break;
                    }
                    send(fd, buf, n, 0);
                }
            }
        }
    }
    close(listenfd);
    return 0;
}
```

### 5.5 关键要点

1. **每次循环重新拷贝 fd_set**：`fd_set rset = rfds;`，因为 select 会修改传入的集合（只保留就绪的 fd）
2. **nfds = maxfd + 1**：不是 fd 数量，是最大 fd 值加 1
3. **非阻塞 + 循环 recv 到 EAGAIN**：select 返回时 fd 就绪，但一次 recv 可能没读完，必须循环读到 EAGAIN
4. **断开时 FD_CLR + close**：从主集合移除，关闭 fd

### 5.6 select 的缺点

| 缺点 | 说明 |
|------|------|
| fd 数量限制 | fd_set 固定 1024，超过无法监听 |
| 每次遍历全部 fd | `for (fd = 0; fd < maxfd; fd++)`，即使大部分 fd 没就绪也要检查 |
| 每次拷贝 fd_set | 用户态→内核态拷贝，连接多时开销大 |
| 每次重新设置 | select 修改集合，每次调用前要重新拷贝 |

### 5.7 踩坑：select 和多线程混用

**错误写法**：select 返回就绪后，为每个就绪 fd 创建线程处理，把 rfds 按值传给线程。

```cpp
// ❌ 错误：rfds 按值传递，线程里 FD_CLR 修改的是副本
void client_thread(int clientfd, fd_set rfds) {
    // ...
    FD_CLR(clientfd, &rfds);  // 修改的是副本，主集合没变化！
    close(clientfd);
}

// ❌ 错误：FD_ISSET 检查错了集合
for (int fd = listenfd + 1; fd <= maxfd; fd++) {
    if (FD_ISSET(fd, &rfds)) {  // 应该检查 rset（select 返回的就绪集合），不是 rfds
        std::thread t(client_thread, fd, rfds);
        t.detach();
    }
}
```

**导致的问题**：`select: Bad file descriptor` —— 线程里 close 了 fd，但主集合 rfds 里还有这个 fd，下次 select 检查已关闭的 fd 报错。

**正确做法**：select 版本不要用多线程，单线程顺序处理所有就绪 fd。

## 六、版本4：poll 多路复用

### 6.1 目标

和 select 一样是 IO 多路复用，但去掉 1024 限制，用数组管理 fd，不需要每次重新拷贝整个集合。

### 6.2 poll 函数详解

```cpp
#include <poll.h>
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
```

| 参数 | 含义 |
|------|------|
| `fds` | pollfd 数组，每个元素描述一个 fd 的监听事件 |
| `nfds` | 数组中有效元素的个数 |
| `timeout` | 超时毫秒数，-1 表示永久阻塞 |

**返回值**：就绪的 fd 总数，超时返回 0，出错返回 -1。

### 6.3 pollfd 结构体

```cpp
struct pollfd {
    int   fd;      // 文件描述符，设为 -1 表示该槽位空闲
    short events;  // 用户要监听的事件（输入）
    short revents; // 内核返回的就绪事件（输出）
};
```

**events 和 revents 的关系**：
- `events`：用户告诉内核"我想监听这个 fd 的什么事件"，比如 `POLLIN`（可读）
- `revents`：内核告诉用户"这个 fd 实际发生了什么事件"，比如 `POLLIN`（有数据可读）
- 两者用的是同一组宏，但方向不同：events 是输入，revents 是输出
- **revents 根据内核实际检测到的事件返回**，不一定和 events 完全一样（比如 events 只设了 POLLIN，但 revents 可能同时有 POLLIN 和 POLLERR）

**常用事件宏**：

| 宏 | 含义 |
|----|------|
| `POLLIN` | 有数据可读 |
| `POLLOUT` | 可写（发送缓冲区有空间） |
| `POLLERR` | 错误 |
| `POLLHUP` | 对端挂断 |
| `POLLNVAL` | fd 无效 |

### 6.4 代码模板

```cpp
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <stdio.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <fcntl.h>
#include <errno.h>
#include <poll.h>

#define MAX_FDS 1024

int main() {
    // socket/bind/listen 同版本1，省略...

    struct pollfd fds[MAX_FDS];
    for (int i = 0; i < MAX_FDS; i++) {
        fds[i].fd = -1;  // 初始化为空闲
    }
    fds[0].fd = listenfd;
    fds[0].events = POLLIN;
    int max_index = 0;

    while (1) {
        int nready = poll(fds, max_index + 1, -1);
        if (nready == -1) { perror("poll"); break; }

        // 检查监听 fd
        if (fds[0].revents & POLLIN) {
            struct sockaddr_in client_addr;
            socklen_t len = sizeof(client_addr);
            int connfd = accept(listenfd, (struct sockaddr*)&client_addr, &len);
            if (connfd == -1) { perror("accept"); continue; }

            // 设置非阻塞
            int flags = fcntl(connfd, F_GETFL, 0);
            flags |= O_NONBLOCK;
            fcntl(connfd, F_SETFL, flags);

            // 找一个空槽位
            int slot = -1;
            for (int j = 1; j < MAX_FDS; j++) {
                if (fds[j].fd == -1) { slot = j; break; }
            }
            if (slot == -1) {
                std::cerr << "too many clients" << std::endl;
                close(connfd);
                continue;
            }
            fds[slot].fd = connfd;
            fds[slot].events = POLLIN;
            if (slot > max_index) max_index = slot;
        }

        // 检查所有客户端 fd
        for (int i = 1; i <= max_index; i++) {
            if (fds[i].revents & POLLIN) {
                int fd = fds[i].fd;
                char buf[1024];
                while (1) {
                    memset(buf, 0, sizeof(buf));
                    int n = recv(fd, buf, sizeof(buf), 0);
                    if (n == 0) {
                        // 客户端断开
                        std::cout << "断开客户端fd：" << fd << std::endl;
                        close(fd);
                        fds[i].fd = -1;  // 标记为空闲
                        break;
                    } else if (n < 0) {
                        if (errno == EAGAIN) break;
                        perror("recv");
                        close(fd);
                        fds[i].fd = -1;
                        break;
                    }
                    send(fd, buf, n, 0);
                }
            }
        }
    }
    close(listenfd);
    return 0;
}
```

### 6.5 poll vs select

| 对比项 | select | poll |
|--------|--------|------|
| fd 集合 | fd_set 位图，固定 1024 | pollfd 数组，无固定限制 |
| 每次调用 | 重新拷贝整个 fd_set | 不需要拷贝，内核直接修改 revents |
| 遍历 | 从 0 到 maxfd 全部遍历 | 遍历数组有效元素 |
| 新增 fd | FD_SET，自动管理 | 需要找空槽位 |
| 断开处理 | FD_CLR | fd 设为 -1 |

**poll 的缺点**：仍然要遍历全部 fd 检查 revents，连接多时 O(n) 遍历开销大。

### 6.6 踩坑记录

1. **close(-1)**：断开时先 `fds[i].fd = -1` 再 `close(fds[i].fd)`，导致 close(-1)。应该先保存 fd，close 后再设 -1。
   ```cpp
   int temp_fd = fds[i].fd;  // 先保存
   close(temp_fd);             // 关闭
   fds[i].fd = -1;             // 再标记空闲
   ```

2. **新连接不找空槽位，直接 max_index++**：连接断开后槽位空了，但新连接不用空槽位，直接往后加，数组很快越界。必须遍历找 `fd == -1` 的空槽位。

3. **n==0 分支缺 break**：客户端断开后没有 break，继续执行后面的 recv 逻辑，对已关闭的 fd 操作。

## 七、版本5：epoll 多路复用

### 7.1 目标

epoll 是 Linux 特有的高性能 IO 多路复用，只返回就绪的 fd，不需要遍历全部 fd，支持百万级并发。

### 7.2 epoll 三个核心函数

#### epoll_create —— 创建 epoll 实例

```cpp
#include <sys/epoll.h>
int epoll_create(int size);
int epoll_create1(int flags);  // 推荐，flags 传 EPOLL_CLOEXEC
```

返回一个 epoll fd（epfd），内部维护一个红黑树（管理所有监听的 fd）和一个就绪链表（存放就绪的 fd）。

> `size` 参数在现代 Linux 中已忽略，只要 > 0 就行。推荐用 `epoll_create1(EPOLL_CLOEXEC)`，fork 子进程时自动关闭 epfd。

#### epoll_ctl —— 管理 fd（增删改）

```cpp
int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
```

| op | 含义 |
|----|------|
| `EPOLL_CTL_ADD` | 把 fd 加入 epoll，注册监听事件 |
| `EPOLL_CTL_MOD` | 修改 fd 的监听事件 |
| `EPOLL_CTL_DEL` | 把 fd 从 epoll 移除 |

#### epoll_wait —— 等待事件

```cpp
int epoll_wait(int epfd, struct epoll_event *events, int maxevents, int timeout);
```

| 参数 | 含义 |
|------|------|
| `epfd` | epoll fd |
| `events` | 输出数组，存放就绪的事件 |
| `maxevents` | 数组大小 |
| `timeout` | 超时毫秒，-1 永久阻塞 |

**返回值**：就绪的 fd 数量，超时返回 0，出错返回 -1。

> ⚠️ epoll_wait 只返回**就绪的** fd，不需要遍历全部 fd，这是 epoll 高性能的核心原因。

### 7.3 epoll_event 结构体

```cpp
struct epoll_event {
    uint32_t     events;  // 监听的事件 / 返回的就绪事件
    epoll_data_t data;    // 用户数据，可以存 fd 或指针
};

typedef union epoll_data {
    void    *ptr;   // 存指针（比如 Channel* 对象地址）
    int      fd;    // 存 fd
    uint32_t u32;
    uint64_t u64;
} epoll_data_t;
```

**常用事件宏**：

| 宏 | 含义 |
|----|------|
| `EPOLLIN` | 可读 |
| `EPOLLOUT` | 可写 |
| `EPOLLERR` | 错误（自动监听，不需要手动加） |
| `EPOLLHUP` | 对端挂断（自动监听） |
| `EPOLLET` | 边缘触发模式（默认是水平触发） |
| `EPOLLONESHOT` | 只触发一次，处理完需要重新注册 |

### 7.4 LT 水平触发 vs ET 边缘触发（重点）

| 对比项 | LT（水平触发，默认） | ET（边缘触发） |
|--------|---------------------|---------------|
| 触发条件 | 缓冲区**有数据**就一直触发 | 缓冲区**从无到有**时触发一次 |
| 数据没读完 | 下次 epoll_wait 还会触发 | **不会再触发**，数据丢失 |
| 处理方式 | recv 一次就行（但建议循环） | **必须循环 recv 到 EAGAIN** |
| 性能 | 较低（可能重复触发） | 高（只触发一次） |
| 编程难度 | 简单 | 复杂（必须非阻塞+循环读） |

> ⚠️ ET 模式必须配合非阻塞 socket，且必须循环 recv 到 EAGAIN，否则数据丢失。

### 7.5 代码模板（LT 水平触发）

```cpp
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <stdio.h>
#include <sys/socket.h>
#include <sys/epoll.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <fcntl.h>
#include <errno.h>

#define MAX_EVENTS 1024

int main() {
    // socket/bind/listen 同版本1，省略...

    // 1. 创建 epoll 实例
    int epfd = epoll_create1(EPOLL_CLOEXEC);
    if (epfd == -1) { perror("epoll_create"); return 1; }

    // 2. 把监听 fd 加入 epoll
    struct epoll_event ev;
    ev.events = EPOLLIN;
    ev.data.fd = listenfd;
    epoll_ctl(epfd, EPOLL_CTL_ADD, listenfd, &ev);

    struct epoll_event events[MAX_EVENTS];

    while (1) {
        // 3. 等待事件
        int nready = epoll_wait(epfd, events, MAX_EVENTS, -1);
        if (nready == -1) { perror("epoll_wait"); break; }

        // 4. 只处理就绪的 fd（nready 个）
        for (int i = 0; i < nready; i++) {
            int fd = events[i].data.fd;

            if (fd == listenfd) {
                // 新连接
                struct sockaddr_in client_addr;
                socklen_t len = sizeof(client_addr);
                int connfd = accept(listenfd, (struct sockaddr*)&client_addr, &len);
                if (connfd == -1) { perror("accept"); continue; }

                // 设置非阻塞
                int flags = fcntl(connfd, F_GETFL, 0);
                flags |= O_NONBLOCK;
                fcntl(connfd, F_SETFL, flags);

                // 加入 epoll
                struct epoll_event client_ev;
                client_ev.events = EPOLLIN;  // LT 模式
                client_ev.data.fd = connfd;
                epoll_ctl(epfd, EPOLL_CTL_ADD, connfd, &client_ev);
            } else if (events[i].events & EPOLLIN) {
                // 有数据可读
                char buf[1024];
                while (1) {
                    memset(buf, 0, sizeof(buf));
                    int n = recv(fd, buf, sizeof(buf), 0);
                    if (n == 0) {
                        // 客户端断开
                        epoll_ctl(epfd, EPOLL_CTL_DEL, fd, nullptr);
                        close(fd);
                        break;
                    } else if (n < 0) {
                        if (errno == EAGAIN) break;  // 读完了
                        perror("recv");
                        epoll_ctl(epfd, EPOLL_CTL_DEL, fd, nullptr);
                        close(fd);
                        break;
                    }
                    send(fd, buf, n, 0);
                }
            }
        }
    }
    close(epfd);
    close(listenfd);
    return 0;
}
```

### 7.6 ET 边缘触发版本的区别

只有注册事件时加 `EPOLLET`：
```cpp
client_ev.events = EPOLLIN | EPOLLET;  // 边缘触发
```

其他代码完全一样（已经是循环 recv 到 EAGAIN 了）。ET 模式下，如果一次没读完，下次不会再触发，所以必须确保循环读到 EAGAIN。

### 7.7 epoll vs poll vs select（面试高频）

| 对比项 | select | poll | epoll |
|--------|--------|------|-------|
| fd 数量限制 | 1024（FD_SETSIZE） | 无固定限制 | 无限制（受系统 fd 上限） |
| 每次调用拷贝 | 整个 fd_set 从用户态拷到内核态 | pollfd 数组拷贝 | 只在 ADD/MOD/DEL 时拷贝，wait 不拷贝 |
| 就绪检测 | 遍历全部 fd | 遍历全部 fd | 回调函数，只将就绪 fd 加入链表 |
| 返回后处理 | 遍历全部 fd 检查 FD_ISSET | 遍历全部 fd 检查 revents | 只遍历就绪的 nready 个 |
| 时间复杂度 | O(n) | O(n) | O(1) 监听，O(k) 处理（k 是就绪数） |
| 工作模式 | LT | LT | LT + ET |
| 内核实现 | 位图 | 数组 | 红黑树 + 双向链表 |
| 适用场景 | 连接少且都活跃 | 连接中等 | 连接多且大部分不活跃（高并发） |

### 7.8 踩坑记录

1. **close(listenfd) 写在 while(1) 循环内**：处理一次事件就关闭监听 fd 并 return，服务器只处理一次事件就退出。close 和 return 应该在 while 循环外面。

2. **epoll_ctl DEL 失败直接 exit**：fd 已经 close 后，内核自动从 epoll 移除，再 DEL 返回 ENOENT 是正常的，不应该 exit。打印日志 return 即可。

3. **ET 模式下没循环读到 EAGAIN**：数据只读了一部分，下次不会再触发，剩余数据丢失。必须 while 循环 recv 到 EAGAIN。

4. **listenfd 没设非阻塞**：LT 模式问题不大，但规范做法是所有放到 epoll 的 fd 都非阻塞。大量连接瞬间涌来时，阻塞 accept 有风险。

## 八、并发压测

### 8.1 测试工具：mul_client.c

基于零声课程 `mul_port_client_epoll.c` 改造的单端口并发测试客户端，用 epoll 同时建立大量连接，测试服务器的并发承载能力。

**编译运行**：
```bash
gcc -o mul_client mul_client.c
./mul_client 127.0.0.1 9000 65000  # IP 端口 连接数
```

### 8.2 系统参数调优

压测高并发时需要调整系统参数，否则会遇到各种限制：

#### ulimit —— 单进程 fd 上限

```bash
ulimit -n 65535          # 临时设置当前 shell 的 fd 上限
ulimit -Hn                # 查看硬限制（硬限制不能超过）
ulimit -Sn                # 查看软限制
```

> 硬限制（Hard limit）是上限，软限制（Soft limit）是当前生效值。软限制不能超过硬限制。如果硬限制只有 10240，设 ulimit -n 20480 会报错。

#### ip_local_port_range —— 源端口范围

```bash
cat /proc/sys/net/ipv4/ip_local_port_range
# 默认：32768 60999（只有约 28000 个端口）
sudo sysctl -w net.ipv4.ip_local_port_range="1024 65535"
```

客户端每个连接占用一个源端口，单 IP 最多 65535-1024 ≈ 64000 个连接。这就是压测到 64000 时报 `connect: Cannot assign requested address` 的原因——源端口耗尽。

#### tcp_tw_reuse —— 复用 TIME_WAIT 连接

```bash
sudo sysctl -w net.ipv4.tcp_tw_reuse=1
```

允许复用 TIME_WAIT 状态的连接，缓解短连接压测时端口耗尽。

#### tcp_mem —— TCP 内存压力阈值

```bash
cat /proc/sys/net/ipv4/tcp_mem
# 输出：92715   123620  185430（单位：页，1页=4KB）
# low=362MB, pressure=483MB, high=724MB
```

三个值：
- `low`：低于此值，TCP 内存无压力
- `pressure`：超过此值，内核开始回收内存，连接建立变慢
- `high`：超过此值，内核拒绝分配新的 TCP 内存

**压测现象**：32000 连接左右时，每千连接耗时从 ~1.7s 跳到 ~6.5s，就是因为 TCP 内存超过 pressure 阈值，内核开始回收内存导致连接建立变慢。调整 tcp_mem 可以缓解，但效果有限（因为物理内存是硬限制）。

#### file-max —— 系统全局 fd 上限

```bash
cat /proc/sys/fs/file-max
# 输出：9223372036854775807（WSL 下基本无限制）
```

系统级别的 fd 上限，WSL 下通常很大，不是瓶颈。

### 8.3 压测结果分析

| 连接数区间 | 每千连接耗时 | 原因 |
|-----------|-------------|------|
| 0 ~ 1000 | ~650ms | 初始建立，包含一些初始化开销 |
| 1000 ~ 32000 | ~1.7s | 正常区间，线性增长 |
| 32000 ~ 64000 | ~6.5s ~ 11s | TCP 内存压力（超过 pressure 阈值），内核回收内存导致变慢 |
| 64000+ | 报错 `Cannot assign requested address` | 源端口耗尽（单 IP 上限约 64000） |

**结论**：
- 单端口单 IP 最大约 64000 连接（源端口上限）
- 32000 连接左右出现性能拐点（TCP 内存压力）
- 要突破 64000 需要多 IP（客户端绑定多个 IP）或多机压测
- "百万并发"需要多机压测 + 服务器调优（增加内存、调整 tcp_mem、fd 上限等）

### 8.4 百万并发笔记要点

- 百万并发指的是**同时维持的连接数**，不是每秒请求数（QPS）
- 维持一个空闲连接开销很小（一个 socket 内核对象，约几 KB），所以百万连接在内存足够的服务器上是可行的
- 瓶颈通常在：fd 上限、TCP 内存、源端口（客户端侧）、内存
- epoll 是实现百万并发的关键（O(1) 监听，只处理就绪事件）

## 九、踩坑记录汇总（按出现顺序）

### 编译/拼写类

1. **`perror("lsiten")` 拼写错误** —— 应该是 `perror("listen")`。虽然不影响功能（只是打印的字符串错了），但面试时代码里有拼写错误会扣分。

2. **缺 `errno.h`（误写 `error.h`）** —— `EAGAIN` 未定义，编译报错。正确头文件是 `#include <errno.h>`。

3. **`-o` 输出名和源文件重名** —— `g++ server.cpp -o server.cpp` 会把编译产物覆盖源文件。输出名不要带 `.cpp`。

### 逻辑类

4. **select 和多线程混用导致 `select: Bad file descriptor`** —— rfds 按值传给线程，FD_CLR 修改副本；FD_ISSET 检查错了集合（rfds 而非 rset）。select 版本应该单线程顺序处理。

5. **n==0 分支缺 break** —— 客户端断开（recv 返回 0）后没有 break，继续执行后面的 recv/send 逻辑，对已关闭的 fd 操作。

6. **poll 断开时 `close(-1)`** —— 先 `fds[i].fd = -1` 再 `close(fds[i].fd)`，导致 close(-1)。应该先保存 fd，close 后再设 -1。

7. **poll 新连接不找空槽位，直接 max_index++** —— 连接断开后槽位空了不用，直接往后加，数组很快越界。必须遍历找 `fd == -1` 的空槽位。

8. **epoll `close(listenfd)` 写在 while(1) 循环内** —— 处理一次事件就关闭监听 fd 并 return，服务器只处理一次事件就退出。close 和 return 应该在 while 外面。

9. **用 connfd 直接得到客户端地址** —— connfd 只是一个整数 fd，不能直接得到地址。要用 `getpeername(fd, ...)` 或在 accept 时保存 `client_addr`。且 getpeername 必须在 close 之前调用。

10. **send 返回值未检查** —— 非阻塞模式下 send 可能只发了一部分（发送缓冲区满），需要循环发送直到全部发完，遇到 EAGAIN 等 1ms 重试。

### 网络编程类

11. **字节序没转换** —— 端口直接写 `addr.sin_port = 9000` 而不是 `htons(9000)`，导致端口不对。必须用 htons/htonl 转网络字节序。

12. **`socklen_t` 写成 `int`** —— accept 第三个参数类型不匹配，有隐蔽 bug。必须用 `socklen_t len = sizeof(client_addr);`。

13. **非阻塞 socket 没循环读到 EAGAIN** —— select/poll/epoll 返回时 fd 就绪，但一次 recv 可能没读完。必须 while 循环 recv 到 EAGAIN（非阻塞模式下缓冲区空的标志）。

14. **epoll_ctl DEL 失败直接 exit** —— fd 已经 close 后内核自动移除，再 DEL 返回 ENOENT 是正常的，不应该 exit。打印日志 return 即可。

15. **ET 模式下没循环读到 EAGAIN** —— 边缘触发只在数据从无到有时触发一次，一次没读完下次不会再触发，数据丢失。必须循环读到 EAGAIN。

### 压测类

16. **`ulimit -n 20480` 报错** —— 硬限制（Hard limit）只有 10240，软限制不能超过硬限制。需要先调整硬限制（修改 /etc/security/limits.conf）。

17. **`connect: Cannot assign requested address`** —— 客户端源端口耗尽，单 IP 最多约 64000 个连接。需要调整 ip_local_port_range 或用多 IP/多机压测。

18. **32000 连接后性能骤降** —— TCP 内存超过 pressure 阈值，内核开始回收内存。调整 tcp_mem 可缓解，但物理内存是硬限制。

## 十、面试考点汇总

### TCP 编程基础

1. **TCP 三次握手和四次挥手的过程？**
   - 三次握手：SYN → SYN+ACK → ACK，建立连接
   - 四次挥手：FIN → ACK → FIN → ACK，关闭连接
   - TIME_WAIT 状态：主动关闭方等待 2MSL，确保最后一个 ACK 到达

2. **socket/bind/listen/accept/connect 的作用和调用顺序？**
   - 服务端：socket → bind → listen → accept → recv/send → close
   - 客户端：socket → connect → send/recv → close

3. **accept 返回的 fd 和 listenfd 有什么区别？**
   - listenfd：监听 fd，用来接受新连接，全程只有一个
   - connfd：连接 fd，每个客户端连接一个，用来收发数据

4. **recv 返回 0 是什么意思？**
   - 对端正常关闭连接（TCP FIN），不是错误。此时应该关闭连接。

5. **什么是粘包/半包？怎么解决？**
   - TCP 是流协议，没有消息边界。半包是一次 recv 只读了半个请求，粘包是一次 recv 读到两个请求粘在一起
   - 解决：有限状态机（M3 内容），记住解析状态，累积数据逐行解析

### IO 多路复用

6. **select/poll/epoll 的区别？（高频必考）**
   - 见上方 7.7 对比表
   - 核心：select 有 1024 限制、每次拷贝、遍历全部 fd；poll 去掉 1024 限制但仍遍历；epoll 用红黑树+就绪链表，只返回就绪 fd，O(1) 监听，支持 ET

7. **epoll 的 LT 和 ET 模式区别？**
   - LT（水平触发）：缓冲区有数据就一直触发，recv 一次就行
   - ET（边缘触发）：数据从无到有时触发一次，必须循环 recv 到 EAGAIN，否则数据丢失
   - ET 性能更高但编程更复杂，必须配合非阻塞 socket

8. **epoll 的底层实现？**
   - 红黑树：管理所有注册的 fd，O(log n) 增删改
   - 双向链表：存放就绪的 fd，epoll_wait 直接返回链表中的事件
   - 回调机制：fd 就绪时，内核回调函数把 fd 加入就绪链表

9. **为什么 epoll 比 select 快？**
   - select 每次调用都要拷贝整个 fd_set，且返回后要遍历全部 fd 检查
   - epoll 只在 ADD/MOD/DEL 时拷贝，epoll_wait 不拷贝；且只返回就绪的 fd，不需要遍历全部

10. **什么情况下 select 比 epoll 好？**
    - 连接数少且都很活跃时，select 的开销和 epoll 差不多，且 select 跨平台（epoll 是 Linux 特有）

### 并发与线程

11. **多线程模型和 IO 多路复用模型的区别？**
    - 多线程：每连接一个线程，线程创建/切换开销大，适合连接少但每个连接处理时间长的场景
    - IO 多路复用：一个线程管理多个 fd，没有线程开销，适合连接多但大部分不活跃的场景
    - 实际项目常用"IO 多路复用 + 线程池"：主线程做 IO，线程池做业务处理

12. **什么是惊群效应？epoll 怎么解决？**
    - 惊群：多个进程/线程同时 accept 同一个 listenfd，新连接到来时所有进程都被唤醒，但只有一个能 accept，其他空转
    - epoll 的 EPOLLONESHOT 可以解决：一个 fd 只触发一次，处理完需要重新注册
    - Linux 内核 2.6 后 accept 本身已经解决了惊群（只有一个进程被唤醒）

### 系统调优

13. **高并发服务器需要调优哪些参数？**
    - ulimit -n：fd 上限
    - ip_local_port_range：源端口范围（客户端侧）
    - tcp_tw_reuse：复用 TIME_WAIT 连接
    - tcp_mem：TCP 内存阈值
    - somaxconn：listen 队列长度
    - tcp_max_syn_backlog：SYN 队列长度

14. **TIME_WAIT 状态是什么？有什么影响？怎么处理？**
    - 主动关闭方进入 TIME_WAIT，等待 2MSL（约 1-2 分钟），确保最后一个 ACK 到达
    - 影响：占用端口和内存，大量短连接时端口耗尽
    - 处理：tcp_tw_reuse=1（复用 TIME_WAIT 连接）、tcp_tw_recycle=1（快速回收，已废弃不推荐）、长连接减少短连接
