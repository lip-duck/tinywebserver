# M2 Reactor 事件驱动框架

> 对应零声课程 2.1.2，从"写死的 epoll 服务器"到"可扩展的事件驱动框架"。
> 我的实现是纯 C++ 版本（std::function + lambda），零声课程是 C 风格（typedef 函数指针）。

---

## 一、Reactor 模式概述

### 1.1 为什么需要 Reactor？

M1 的 epoll 代码是**写死的**：
```
epoll_wait 返回 → 判断是 listenfd 就 accept → 是 connfd 就 recv/send
```
所有逻辑堆在 main 循环里，后面加 HTTP 解析、定时器、日志时，循环会越来越臃肿。

**Reactor 的核心思想**：把**事件循环（框架）**和**业务逻辑（回调）**分离。
- 框架（EventLoop）只负责：epoll_wait → 找出哪个 fd 就绪 → 调用这个 fd 绑定的回调函数
- 业务逻辑（accept、recv/send、HTTP解析）写成回调函数，注册到对应 fd 上
- 新增功能只需要写新回调，不用改事件循环

这就是**反转控制（IoC, Inversion of Control）**：不是你的代码调用框架，而是框架在事件发生时调用你的代码。

### 1.2 Reactor vs Proactor（面试必问）

| | Reactor | Proactor |
|---|---------|----------|
| 事件通知时机 | fd **就绪**时通知（可以读/写了） | 读写**完成**后通知（数据已经在缓冲区里了） |
| 谁来读写 | 用户自己读写（非阻塞） | 内核/操作系统完成读写 |
| 典型实现 | Linux epoll + 非阻塞 IO | Windows IOCP |
| 复杂度 | 较低 | 较高 |

Linux 上主要用 Reactor。TinyWebServer 用的就是 Reactor。

## 二、核心类设计

### 2.1 Channel 类（通道）

**职责**：封装一个 fd + 它关心的事件 + 对应的回调函数。类比"事件订阅者"。

```cpp
class Channel {
public:
    Channel(int fd);
    void setReadCallback(std::function<void()> cb);
    void setWriteCallback(std::function<void()> cb);
    void enableReading();           // 注册读事件（events_ |= EPOLLIN）
    void handleEvent();             // 根据 revents_ 调用对应回调
    int fd() const;
    uint32_t events() const;
    void setRevents(uint32_t revents);
private:
    int fd_;                        // 绑定的文件描述符
    uint32_t events_;               // 关心的事件（用户设置，如 EPOLLIN）
    uint32_t revents_;              // 实际发生的事件（由 EventLoop 从 epoll 填入）
    std::function<void()> readCallback_;
    std::function<void()> writeCallback_;
};
```

**关键细节**：
- `events_` 和 `revents_` 的区别：events_ 是"我关心什么"，revents_ 是"实际发生了什么"
- `handleEvent()` 里必须判空：`if (readCallback_) readCallback_();`，否则空回调调用会抛 `std::bad_function_call`

### 2.2 EventLoop 类（事件循环）

**职责**：封装 epoll + 事件循环 + 事件分发。类比"事件中心"。

```cpp
class EventLoop {
public:
    EventLoop();
    ~EventLoop();
    void updateChannel(Channel* channel);   // 注册/更新 channel 到 epoll
    void removeChannel(Channel* channel);   // 从 epoll 移除
    void loop();                             // 事件循环（阻塞在这里）
    void quit();
private:
    int epollfd_;
    bool looping_;
    std::vector<Channel*> channels_;        // 按 fd 索引的 Channel 指针数组
};
```

**关键细节**：
- `channels_` 必须在构造函数里 `resize(MAX_FDS, nullptr)`，否则 `channels_[fd]` 越界
- `epoll_event.data.ptr` 存 Channel 指针（不是 fd），这样 epoll_wait 返回后直接取出 Channel，不需要查找

### 2.3 两个类的关系

```
EventLoop 持有一个 Channel* 数组（按 fd 索引）
每个 fd 对应一个 Channel
epoll_wait 返回 → 从 data.ptr 取出 Channel* → 调用 Channel::handleEvent() → 触发回调
```

## 三、std::function 详解（重点）

### 3.1 是什么

`std::function` 是**可调用对象的通用包装器**，定义在 `<functional>` 头文件里。它可以装：
- 普通函数指针
- lambda 表达式
- `std::bind` 的结果
- 重载了 `operator()` 的类对象（仿函数）

### 3.2 语法

```cpp
std::function<返回类型(参数类型列表)> 变量名;
```

```cpp
#include <functional>

void foo(int x) { std::cout << x; }
std::function<void(int)> f1 = foo;           // 装普通函数
std::function<void(int)> f2 = [](int x){ std::cout << x; };  // 装 lambda
f1(42);  // 调用
f2(42);
```

在 Reactor 里用 `std::function<void()>`——无参数、无返回值的可调用对象。

### 3.3 判空：operator bool()

`std::function` 可以隐式转换为 bool，直接用在 if 里：

```cpp
std::function<void()> f;  // 默认构造，是空的
if (f) { /* 非空 */ }     // false
f = [](){};
if (f) { /* 非空 */ }     // true
```

### 3.4 空调用的后果

如果 `std::function` 是空的（没设置过回调），直接调用会**抛出 `std::bad_function_call` 异常**，程序崩溃：

```cpp
std::function<void()> f;  // 空的
f();                       // ❌ 抛出 std::bad_function_call
```

所以 `Channel::handleEvent()` 里必须先判空：
```cpp
if (revents_ & EPOLLIN) {
    if (readCallback_) readCallback_();  // ✅ 判空再调用
}
```

### 3.5 为什么用 std::function 而不是函数指针？

| | 函数指针 | std::function |
|---|---------|--------------|
| 能装 lambda | ❌ 只能装无捕获的 lambda | ✅ 任意 lambda（包括有捕获的） |
| 能装 bind | ❌ | ✅ |
| 能装仿函数 | ❌ | ✅ |
| 语法 | 复杂（`typedef int (*cb_t)(int)`） | 清晰（`std::function<void(int)>`） |

零声课程用的是 C 风格函数指针（`typedef int (*accept_cb_t)(int fd)`），我的 C++ 版本用 `std::function`，因为需要 lambda 捕获 Channel 指针。

## 四、lambda 表达式详解（重点）

### 4.1 语法

```cpp
[捕获列表](参数列表) mutable -> 返回类型 { 函数体 }
```

| 部分 | 说明 |
|------|------|
| `[捕获列表]` | 从外部作用域抓哪些变量进 lambda |
| `(参数列表)` | lambda 自己的参数，和普通函数一样 |
| `mutable` | 可选，允许修改按值捕获的变量 |
| `-> 返回类型` | 可选，一般能自动推导 |
| `{ 函数体 }` | lambda 被调用时执行的代码 |

### 4.2 捕获列表的六种形式

| 写法 | 含义 |
|------|------|
| `[]` | 不捕获任何外部变量 |
| `[x]` | 按值捕获 x（拷贝一份） |
| `[&x]` | 按引用捕获 x（直接操作原对象） |
| `[=]` | 按值捕获所有用到的外部变量 |
| `[&]` | 按引用捕获所有用到的外部变量 |
| `[&, x]` | x 按值捕获，其他按引用 |
| `[=, &x]` | x 按引用捕获，其他按值 |

### 4.3 在 Reactor 里为什么用 lambda？

`setReadCallback` 要求参数是 `std::function<void()>`——**无参数**的可调用对象。

但 `handleRead` 的签名是 `void handleRead(Channel* ch)`——**需要一个 Channel* 参数**。

直接传 `handleRead` 不行，参数不匹配。所以用 lambda 做一层**适配器**：

```cpp
client_ch->setReadCallback([client_ch]() {
    handleRead(client_ch);
});
```

这个 lambda 本身是无参数的（符合 `std::function<void()>`），但它**捕获了 `client_ch` 指针**，内部调用 `handleRead(client_ch)` 时把参数传进去。

相当于把参数**预绑定**了——lambda 把"函数 + 需要的参数"打包在一起，这就是 lambda 的"闭包"特性。

### 4.4 按值捕获指针 vs 按引用捕获对象

| 场景 | 捕获方式 | 原因 |
|------|---------|------|
| `client_ch`（Channel* 指针，堆对象） | `[client_ch]` 按值捕获 | 捕获的是指针本身（拷贝一个指针，很便宜），两个指针指向同一个 Channel |
| `listenChannel`（Channel 对象，栈上） | `[&listenChannel]` 按引用捕获 | 对象在栈上，不拷贝，操作原对象；生命周期足够长 |

**注意**：按引用捕获要求被捕获的变量在 lambda 调用时仍然有效（生命周期足够长）。栈对象在函数返回后就失效了，这时候按引用捕获会悬空。

## 五、std::move 和移动语义（重点）

### 5.1 左值 vs 右值

| 类型 | 特征 | 例子 |
|------|------|------|
| 左值 | 有名字、能取地址、生命周期长 | `int x = 5;` 里的 `x` |
| 右值 | 临时对象、没名字、表达式结束就销毁 | `5`、`std::string("hello")`、函数返回值 |

### 5.2 拷贝 vs 移动

```cpp
std::string a = "hello";
std::string b = a;            // 【拷贝】a 还在，b 是新副本，要分配内存+复制
std::string c = std::move(a); // 【移动】a 的资源"偷"给 c，a 变空，不需要分配内存+复制
```

**移动的本质**：把对象内部的指针/资源直接转交给新对象，旧对象置空，避免深拷贝。对于持有堆内存的对象（`std::string`、`std::vector`、`std::function`），移动比拷贝快很多。

### 5.3 std::move 真的移动了吗？

**没有。** `std::move` 只是把左值**强制转换成右值引用**，本身不做任何移动操作。真正的移动发生在**移动构造函数**或**移动赋值运算符**里。

```cpp
std::string a = "hello";
std::move(a);  // 只是把 a 转成右值引用，a 的内容没变，也没发生移动
std::string c = std::move(a);  // 这一步才触发移动赋值，a 的资源被 c 拿走
```

### 5.4 值传递 + std::move 的 sink argument 惯用法

在 Reactor 里：
```cpp
void setReadCallback(std::function<void()> cb) {  // 按值传参
    readCallback_ = std::move(cb);                  // 移动赋值给成员变量
}
```

这是现代 C++ 的推荐写法，叫 **"sink argument"（汇点参数）**——参数最终要被成员变量"吸收"。

**为什么比 const 引用好？**

| 调用者传入 | const 引用写法 | 值传递 + move 写法 |
|-----------|--------------|-------------------|
| 左值（已有变量） | 1 次拷贝 | 1 次拷贝 + 1 次移动 |
| 右值（临时 lambda） | 1 次拷贝 | 1 次移动 + 1 次移动 |

- 传入左值时，两种写法差不多（move 很便宜）
- 传入右值（直接传 lambda 临时对象）时，值传递 + move **完全避免拷贝**，只有两次移动，性能更好

而 Reactor 里注册回调最常见的写法就是直接传 lambda 临时对象：
```cpp
channel->setReadCallback([channel]() { handleRead(channel); });
// 这个 lambda 是临时对象（右值）
```

所以值传递 + move 在这种场景下性能最优。

### 5.5 移动后的对象还能用吗？

移动后的对象处于**"有效但未指定"（valid but unspecified）**状态：
- 可以重新赋值
- 可以销毁
- 不要依赖它的值（比如 std::string 移动后可能是空的，也可能不是，取决于实现）

## 六、关键函数细节

### 6.1 EventLoop::updateChannel()

```cpp
void updateChannel(Channel* channel) {
    struct epoll_event ev;
    ev.events = channel->events();
    ev.data.ptr = channel;  // 【关键】把 Channel 指针存在 data.ptr 里
    epoll_ctl(epollfd_, EPOLL_CTL_ADD, channel->fd(), &ev);
    channels_[channel->fd()] = channel;
}
```

**为什么 data.ptr 存 Channel 指针而不是 fd？**
- 存 fd 的话，epoll_wait 返回后还要根据 fd 去 channels_ 数组里查找 Channel（虽然是 O(1) 数组索引，但多一步）
- 存指针的话，epoll_wait 返回后直接取出 Channel*，**零查找**，直接调用回调
- 这是 Reactor 的精髓之一

### 6.2 EventLoop::loop()

```cpp
void loop() {
    looping_ = true;
    struct epoll_event events[MAX_EVENTS];
    while (looping_) {
        int nready = epoll_wait(epollfd_, events, MAX_EVENTS, -1);
        if (nready == -1) {
            if (errno == EINTR) continue;  // 被信号中断，重试
            perror("epoll_wait");
            break;
        }
        for (int i = 0; i < nready; i++) {
            Channel* channel = static_cast<Channel*>(events[i].data.ptr);
            channel->setRevents(events[i].events);  // 填入实际发生的事件
            channel->handleEvent();                   // 调用回调
        }
    }
}
```

**关键点**：
- 循环里**没有任何业务逻辑**（没有 accept、recv、send），业务全在回调里
- `epoll_wait` 返回 -1 时要处理 `EINTR`（被信号中断），不是真正的错误
- 只遍历 `nready` 个就绪事件，不是遍历所有 fd（这是 epoll 比 select/poll 快的原因）

### 6.3 Channel::handleEvent()

```cpp
void handleEvent() {
    if (revents_ & EPOLLIN) {
        if (readCallback_) readCallback_();
    }
    if (revents_ & EPOLLOUT) {
        if (writeCallback_) writeCallback_();
    }
}
```

**关键点**：
- 用**位与**（`&`）而不是等于（`==`），因为 revents_ 可能同时有多个位（比如 EPOLLIN | EPOLLHUP）
- 必须判空，否则空回调崩溃
- EPOLLIN 和 EPOLLOUT 是两个独立的 if，不是 if-else，因为可能同时就绪

### 6.4 handleAccept()（业务回调）

```cpp
void handleAccept(Channel* ch) {
    int connfd = accept(ch->fd(), ...);
    // 设置非阻塞
    int flags = fcntl(connfd, F_GETFL, 0);
    fcntl(connfd, F_SETFL, flags | O_NONBLOCK);

    Channel* client_ch = new Channel(connfd);
    client_ch->enableReading();
    client_ch->setReadCallback([client_ch]() { handleRead(client_ch); });
    g_loop->updateChannel(client_ch);
}
```

**关键点**：
- 新连接的回调必须设到 **client_ch** 上，不是 ch（listen_ch）上——这是我踩过的坑
- client_ch 用 `new` 创建（堆对象），因为它的生命周期不固定，客户端断开时在 handleRead 里 `delete`
- listen_ch 可以用栈对象（生命周期和 main 一样长）

### 6.5 handleRead()（业务回调）

```cpp
void handleRead(Channel* ch) {
    int fd = ch->fd();
    char buf[1024];
    while (true) {
        int n = recv(fd, buf, sizeof(buf), 0);
        if (n == 0) {
            // 客户端断开
            g_loop->removeChannel(ch);
            close(fd);
            delete ch;  // Channel 是 new 出来的，断开时释放
            return;
        } else if (n < 0) {
            if (errno == EAGAIN || errno == EWOULDBLOCK) break;  // 读完了
            // 真正的错误
            g_loop->removeChannel(ch);
            close(fd);
            delete ch;
            return;
        }
        send(fd, buf, n, 0);  // 回显
    }
}
```

**关键点**：
- 非阻塞 + while 循环读到 EAGAIN（ET 模式必须这么做，LT 模式也建议这么做）
- `n == 0` 是客户端正常断开（FIN）
- `n < 0 && errno == EAGAIN` 是数据读完了，不是错误
- 断开时必须 `delete ch`，否则内存泄漏
- 必须先 `removeChannel` 再 `close` 再 `delete`，顺序不能乱

## 七、我踩过的坑（第二遍手敲时的错误）

> 第二遍凭理解手敲，暴露了第一遍抄模板没注意到的问题。

### 坑1：handle_accept 里回调设错了对象（最严重）

```cpp
// ❌ 错误
channel* client_ch = new channel(connfd);
client_ch->setreadevents();
ch->setreadcallback([client_ch]() { handle_read(client_ch); });
//  ↑ 这里是 ch（listen_ch），不是 client_ch！

// ✅ 正确
client_ch->setreadcallback([client_ch]() { handle_read(client_ch); });
```

**后果**：新连接没有读回调，listen_ch 的回调被覆盖成 handle_read，第二个连接进来就崩溃。
**教训**：新连接的回调必须设到新创建的 client_ch 上，手敲时要特别注意变量名。

### 坑2：channels_ vector 没有 resize

```cpp
// ❌ 错误：构造函数里没 resize
eventloop() {
    epollfd_ = epoll_create(1);
    // 没有 channels_.resize(MAX_FDS, nullptr);
}
// updateChannel 里直接 channels_[ch->getfd()] = ch → 越界访问空 vector

// ✅ 正确
eventloop() {
    epollfd_ = epoll_create(1);
    channels_.resize(MAX_FDS, nullptr);
}
```

**后果**：vector 下标访问不存在的元素是未定义行为，段错误。
**教训**：用下标访问 vector 前必须确保容量足够。

### 坑3：handle_events 里回调没有判空

```cpp
// ❌ 错误
void handle_events() {
    if (revents_ & EPOLLIN) {
        readcallback_();  // 空回调直接调用，抛异常
    }
}

// ✅ 正确
void handle_events() {
    if (revents_ & EPOLLIN) {
        if (readcallback_) readcallback_();
    }
}
```

**后果**：只设了写回调没设读回调的 channel，EPOLLIN 触发时调用空 std::function，抛 `std::bad_function_call`。
**教训**：std::function 调用前必须判空。

### 坑4：缺少头文件

- 用了 `errno`、`EAGAIN`、`EWOULDBLOCK` 但没包含 `<errno.h>`
- 用了 `sockaddr_in`、`htons` 但没包含 `<netinet/in.h>`（可能被 `<arpa/inet.h>` 间接包含，但不保证）

### 坑5：getevents() 返回类型不匹配

```cpp
int getevents() const { return events_; }  // events_ 是 uint32_t，返回 int
```

不影响功能（int 足够装下 EPOLLIN），但类型不严谨，应该返回 `uint32_t`。

## 八、零声 C 风格 Reactor vs 我的 C++ Reactor

| 维度 | 零声课程（C 风格） | 我的实现（C++） |
|------|-------------------|----------------|
| 回调机制 | `typedef` 函数指针 | `std::function` + lambda |
| 连接上下文 | `struct conn_item`（fd + buffer + 三个回调指针） | `Channel` 类（fd + events + revents + 两个回调） |
| fd → 上下文查找 | `connlist[fd]` 数组（全局变量） | `channels_[fd]` vector（EventLoop 成员） |
| epoll_event.data | 存 fd | 存 Channel* 指针 |
| 事件分发 | main 里 if-else 判断 fd 类型 | Channel::handleEvent() 统一分发 |
| 缓冲区 | conn_item 里自带 buffer | 当前回显版本用局部 buf，M5 才加 Buffer 类 |
| 写事件切换 | recv 后 set_event(fd, EPOLLOUT, MOD) | 当前回显版本不需要，一直 EPOLLIN |

零声的 C 风格代码在 `http服务器.md` 里，可以对照看。

## 九、面试考点清单

1. **Reactor 模式的原理？** → 事件驱动，epoll_wait 返回后根据 fd 调用绑定的回调，框架和业务分离。
2. **Reactor vs Proactor？** → Reactor 就绪时通知用户自己读写；Proactor 内核完成读写后通知。Linux 用 Reactor，Windows IOCP 用 Proactor。
3. **为什么 `epoll_event.data.ptr` 存 Channel 指针？** → 零查找，直接取出 Channel 调用回调，不需要根据 fd 查找。
4. **std::function 和函数指针的区别？** → std::function 能装 lambda（有捕获）、bind、仿函数；函数指针只能装普通函数和无捕获 lambda。
5. **lambda 的捕获列表有哪些形式？** → [] [x] [&x] [=] [&] [&,x] [=,&x]。
6. **为什么用值传递 + std::move？** → sink argument 惯用法，传入右值（临时 lambda）时避免拷贝，性能最优。
7. **std::move 真的移动了吗？** → 没有，只是把左值转成右值引用，真正的移动在移动构造/移动赋值里。
8. **非阻塞 IO 和 Reactor 的关系？** → Reactor 必须配合非阻塞 IO，否则回调里 recv 阻塞会导致事件循环卡住，其他 fd 饿死。
9. **Channel 和 EventLoop 的职责划分？** → Channel 封装 fd+事件+回调；EventLoop 封装 epoll+循环+分发。
10. **什么是反转控制（IoC）？** → 框架调用你的代码，而不是你的代码调用框架。
